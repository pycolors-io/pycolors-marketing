Le registre PyColors est une couche de distribution sur les paquets PyColors publics et la source canonique Block. Son premier pilote combine `pycolors-base` avec `feedback-empty-state-panel`, en utilisant l'interface de ligne de commande shadcn amont plutôt qu'un nouvel installateur PyColors.

## Choisissez votre surface d'installation [#choose-your-installation-surface]

- **Paquets npm publics :** utilisation [Installation de l'interface utilisateur](/docs/ui/installation) lorsque vous composez vos propres interfaces. `@pycolors/ui` et `@pycolors/tokens` restent des dépendances avec des exportations publiques.
- **Source du bloc manuel :** utilisation [Installation des blocs](/docs/blocks) pour copier directement un motif documenté. Vous configurez vous-même les dépendances et les styles et possédez le code copié.
- **Pilote du registre :** utiliser le [Guide d'installation du registre](/docs/registry/installation) pour inspecter la configuration de base et le premier élément gratuit avant de les appliquer à une application existante compatible. La vérification des transports publics reste une condition préalable.

L'installation du registre ne fait pas de la source copiée un paquet npm mis à jour automatiquement. Il ne fournit pas d'authentification, de facturation, de registre privé ou de téléchargements premium. Il n'y a pas `@pycolors/blocks` paquet ou propriétaire `pycolors init`, `add`ou `doctor` commande dans ce workflow.

## Compatibilité testée [#tested-compatibility]

Les preuves d'installation couvrent ces scénarios exacts, pas toutes les versions dans une gamme complète:

- Next.js **16.1.1**, App Router, application autonome.
- Vite **8.0.0**, React application, autonome.
- La même application dans **`apps/web` d'un espace de travail pnpm**, avec une configuration locale de l'application et un espace de travail frère inchangé.

Les versions communes sont **Node 24**, **pnpm 10.32.1**, **shadcn 4.19.0**,
**React et React DOM 19.2.0**, **TypeScript 6.0.3**et **Tailwind CSS et son plugin PostCSS 4.3.3**. La matrice installe le public **`@pycolors/ui` 1.5.2**,
**`@pycolors/tokens` 1.2.2**et **`lucide-react` 1.47.0**. Son outillage de qualité utilise ESLint 9.39.5, eslint-config-next 16.1.1 et Prettier 3.9.6.

La configuration requise est stricte TypeScript/TSX, `radix-nova`, Lucide, variables CSS, classes Tailwind non préfixées, et alias locaux à l'application consommatrice. La feuille de style est `src/app/globals.css` pour Next.js ou `src/styles/globals.css` pour Vite, par rapport à cette application. Vite conserve la base `rsc: true` Paramètre CLI ; cela ne donne pas de composants de serveur de Vite React.

Les autres frameworks ou gestionnaires de packages, la sortie JavaScript, l'interface utilisateur de base, les autres styles, Tailwind 3, les classes préfixées, les différentes profondeurs de feuille de style, la configuration TypeScript héritée et les alias d'applications croisées sont en dehors de ce chemin testé. Commencez par l'installation manuelle plutôt que de supposer que la CLI rejettera en toute sécurité une configuration non prise en charge.

## Ce que prouvent les chèques [#what-the-checks-prove]

Les trois scénarios fonctionnent deux fois chacun avec des projets froids et des magasins de colis. Ils installent de véritables dépendances publiques npm, valident le placement de fichiers et CSS, exercent des conflits d'installation et de fichiers répétés, et exécutent le formatage, les types lint, stricts, les tests de source installés et les builds de production. Les scripts de cycle de vie de dépendance sont désactivés dans ces montages.

Les tests résolvent les artefacts de registre locaux générés. Une charge utile de test temporaire mappe la dépendance de base du pilote à l'artefact de base local ; le manifeste faisant autorité et la source générée originale ne sont pas modifiés. Le test de consommation hors ligne distinct exerce également l'inspection d'article avec `view`.

C’est la preuve de l’installation d’artefacts, et non de la livraison en direct de GitHub, de chaque future résolution de dépendance, de l’interaction du navigateur ou de l’accessibilité visuelle. Les [guide d'installation](/docs/registry/installation) explique l'adressage public et la limite de transport restante.
