### Choix booléens pour les formulaires et les paramètres de produits [#boolean-choices-for-forms-and-product-settings]

Les **Case à cocher** Le composant permet aux utilisateurs de sélectionner une ou plusieurs options dans une liste, de confirmer un paramètre ou d’opter pour une condition spécifique.

Utilisez-le pour:

- paramètres basculent qui peuvent être sélectionnés indépendamment
- filtres à sélection multiple
- termes, consentement et champs de confirmation
- préférences groupées
- flux de produits de type checklist
- choix de forme facultatifs

Checkbox est construit sur **Boîte à cocher Radix** et stylisé avec des tokens sémantiques PyColors tels que `border-input`, `bg-background`, `text-foreground`et `ring-ring`.

<Callout title="Idée de base">
  La case à cocher est pour la sélection explicite. Utilisez-le lorsque chaque
  option peut être cochée ou décochée indépendamment.

</Callout>

import {
  Checkbox,
  CheckboxField,
  CheckboxContent,
  CheckboxLabel,
  CheckboxDescription,

export function ControlledCheckbox() {
  const [checked, setChecked] = React.useState(true);

### État indéterminé [#indeterminate-state]

Utilisez l'état indéterminé pour les cases à cocher parent lorsque seuls certains éléments enfants sont sélectionnés.

Utilisation `checked="indeterminate"` lorsque votre application est la propriété de l'État, ou `defaultChecked="indeterminate"` pour une sélection partielle initiale non contrôlée. Appuyez sur Espace pour sélectionner une case à cocher partielle non contrôlée. À l'intérieur d'un formulaire, un bouton de réinitialisation natif restaure son état initial, y compris le tiret de sélection partielle.

### Validation du formulaire [#form-validation]

Utilisez le `error` prop lorsqu'une case à cocher requise n'est pas sélectionnée. Il rend visible la copie d'erreur, définit `aria-invalid`, et relie le message aux deux `aria-describedby` et `aria-errormessage`. L'erreur a `role="alert"`Il est donc annoncé lorsqu'il apparaît. Fourni par les consommateurs `aria-describedby` Les valeurs sont conservées à côté de l'identifiant du message d'erreur.

## Checkbox vs Switch vs Radio Group [#checkbox-vs-switch-vs-radio-group]

| Situation                                      | Utilisation                         |
| ---------------------------------------------- | ----------------------------------- |
| Sélections indépendantes multiples             | Case à cocher                       |
| Consentement ou confirmation requis            | Case à cocher                       |
| Sélection de parents avec des enfants mixtes   | Case à cocher avec état indéterminé |
| Mise en marche/arrêt immédiate                 | Commutateur                         |
| Un choix parmi un groupe mutuellement exclusif | Groupe Radio                        |
| Petite liste d'actions de menu                 | Menu déroulant                      |

<Callout title="Règle de décision">
  Utilisez la case à cocher pour la sélection, le commutateur pour l'activation
  immédiate et le groupe Radio pour un choix exclusif.

</Callout>

## API [#api]

#### Composants [#components]

| Composante            | Désignation                                                |
| --------------------- | ---------------------------------------------------------- |
| `Checkbox`            | Contrôle de la case à cocher racine construit sur Radix    |
| `CheckboxField`       | Aide à la mise en page pour les lignes de case à cocher    |
| `CheckboxContent`     | Aide à la pile de texte pour l'étiquette et la description |
| `CheckboxLabel`       | Aide-étiquette accessible                                  |
| `CheckboxDescription` | Texte d'appui                                              |

#### Cocher les props [#checkbox-props]

| Prop              | Type                         | Par défaut | Désignation                                         |
| ----------------- | ---------------------------- | ---------- | --------------------------------------------------- |
| `checked`         | `boolean \| "indeterminate"` | —          | État contrôlé vérifié                               |
| `defaultChecked`  | `boolean \| "indeterminate"` | —          | État initial vérifié sans contrôle                  |
| `onCheckedChange` | `(checked) => void`          | —          | Appelé lorsque l'état vérifié change                |
| `disabled`        | `boolean`                    | `false`    | Désactive la case à cocher                          |
| `required`        | `boolean`                    | `false`    | Cochez la case au besoin                            |
| `error`           | `string`                     | —          | Rend une erreur annoncée et définit l'état invalide |
| `name`            | `string`                     | —          | Nom du champ de formulaire                          |
| `value`           | `string`                     | —          | Valeur du formulaire soumis                         |
| `className`       | `string`                     | —          | Autres classes Tailwind                             |

`Checkbox` étend Radix Checkbox Root props.

### Accessibilité [#accessibility]

Checkbox est construit sur les primitives Radix Checkbox.

Cela signifie :

- L'interaction du clavier est gérée
- Les états vérifiés et indéterminés sont exposés aux technologies d'assistance.
- L'état désactivé est exposé correctement
- focus style utilise PyColors ring tokens
- L'utilisation des formulaires fonctionne grâce à la sémantique des formulaires natifs
- `error` rend visible la copie d'erreur et les fils `aria-invalid`,
  `aria-describedby`et `aria-errormessage`

Directives :

- fournir une étiquette visible pour chaque case à cocher
- connecter des étiquettes en utilisant `htmlFor` et `id`
- utiliser des descriptions pour des choix ayant des conséquences
- Ne comptez pas uniquement sur la couleur pour les états de validation
- utiliser le `error` prop pour les confirmations requises non valides
- Gardez les étiquettes courtes et orientées vers l'action

<Callout title="Règle d'accessibilité">
  Une case à cocher a besoin d'un nom accessible clair. L'étiquette doit avoir
  un sens même lorsqu'elle est lue sans contexte.

</Callout>

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Les paramètres doivent-ils utiliser Checkbox ou Switch ?">
    Utilisez la case à cocher lorsque l'utilisateur sélectionne une option dans le cadre d'un formulaire plus grand. Utilisez Switch lorsque le réglage change immédiatement et se comporte comme un contrôle marche/arrêt.
  </Accordion>

<Accordion title="Quand devrais-je utiliser indéterminé?">
  Utilisez indéterminée lorsqu'une case à cocher parent représente un groupe où
  seuls certains éléments enfants sont sélectionnés.
</Accordion>

<Accordion title="Est-ce que Checkbox peut être utilisé à l'intérieur des formulaires ?">
  Oui. Utilisation `name`, `value`, `required`, et copie de validation lorsque
  la case à cocher participe à la soumission du formulaire.
</Accordion>

  <Accordion title="Chaque case à cocher doit-elle avoir une description ?">
    Non. Utilisez des descriptions uniquement lorsque le choix a besoin de clarification ou a des conséquences. Les choix simples ne peuvent utiliser qu'une étiquette.
  </Accordion>
</Accordions>
