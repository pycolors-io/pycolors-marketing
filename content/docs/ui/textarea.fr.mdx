### Entrée multi-lignes pour une intention utilisateur plus longue [#multi-line-input-for-longer-user-intent]

Les **Textarea** Le composant capture un texte plus long qu'une entrée standard.

Utilisez-le pour:

- messages de rétroaction
- Demandes d'assistance
- descriptions de produits
- notes
- invites
- commentaires
- Champs de formulaire plus longs

Textarea suit le même modèle de champ `Input`: étiquette, texte d'aide, état de l'erreur, identifiant généré et descriptions accessibles.

<Callout title="Idée de base">
  Utilisez Textarea lorsque l'utilisateur a besoin d'espace pour exprimer une
  intention, un contexte ou une explication.

</Callout>

### État de l'erreur [#error-state]

Utilisez le `error` prop pour les erreurs de validation. Il définit automatiquement `aria-invalid`, `aria-errormessage`, et le style d'erreur. Le texte de l'erreur `role="alert"`, il est donc annoncé immédiatement lorsqu'il apparaît - y compris lorsque le champ est déjà ciblé. Un produit fourni par le consommateur `aria-describedby` est composé avec les ids helper/error du champ plutôt que remplacé.

### Guide des tailles [#size-guidance]

| Taille | Idéal pour                                              |
| ------ | ------------------------------------------------------- |
| `sm`   | Notes compactes, tables d'administration, formes denses |
| `md`   | Formulaires et pages de paramètres par défaut           |
| `lg`   | Longues descriptions, invites, messages de soutien      |

### Options de redimensionnement disponibles [#available-resize-options]

| Redimensionner | Comportement                                               |
| -------------- | ---------------------------------------------------------- |
| `vertical`     | L'utilisateur peut redimensionner la hauteur               |
| `none`         | Taille fixe                                                |
| `horizontal`   | L'utilisateur peut redimensionner la largeur               |
| `both`         | L'utilisateur peut redimensionner la largeur et la hauteur |

<Callout title="Règle de redimensionnement">
  Préférez `vertical` pour la plupart des formes de produits. Évitez le
  redimensionnement horizontal dans les mises en page contraintes.

</Callout>

### Utilisations [#usage-patterns]

<Steps>
  <Step>
    #### Utiliser Textarea pour des réponses plus longues [#use-textarea-for-longer-answers]

    Utilisez Input pour les valeurs courtes. Utilisez Textarea lorsque l'utilisateur doit fournir du contexte, des explications ou du contenu multiligne.

</Step>

  <Step>
    #### Gardez les étiquettes explicites [#keep-labels-explicit]

    L'étiquette doit décrire le contenu attendu de l'utilisateur, pas l'élément d'interface utilisateur lui-même.

</Step>

  <Step>
    #### Ajouter du texte d'aide pour les champs complexes [#add-helper-text-for-complex-fields]

    Utilisez le texte d'aide lorsque le champ a besoin d'exemples, de contraintes ou de conseils de mise en forme.

</Step>

  <Step>
    #### Valider avec des erreurs actionnables [#validate-with-actionable-errors]

    Les messages d'erreur doivent expliquer ce qu'il faut changer, pas seulement que la valeur est invalide.

</Step>

  <Step>
    #### Choisissez redimensionner intentionnellement [#choose-resize-intentionally]

    Utilisez le redimensionnement vertical pour un contenu flexible. N'utilisez pas de redimensionnement pour les surfaces contrôlées comme les feuilles et les cartes compactes.

</Step>

</Steps>

## Textarea vs Input [#textarea-vs-input]

| Situation              | Utilisation |
| ---------------------- | ----------- |
| Nom, email, URL, slug  | Entrées     |
| Recherche de requête   | Entrées     |
| Titre abrégé           | Entrées     |
| Message de rétroaction | Textarea    |
| Description du produit | Textarea    |
| Notes ou commentaires  | Textarea    |
| AI prompt              | Textarea    |

<Callout title="Règle de décision">
  Si la réponse attendue peut tenir naturellement sur une ligne, utilisez
  Entrée. Si l'utilisateur a besoin d'expliquer quelque chose, utilisez
  Textarea.

</Callout>

## API [#api]

| Prop         | Type                                                | Par défaut   | Désignation                                           |
| ------------ | --------------------------------------------------- | ------------ | ----------------------------------------------------- |
| `label`      | `string`                                            | —            | Étiquette accessible affichée au-dessus du texte      |
| `helperText` | `string`                                            | —            | Texte de soutien affiché lorsqu'il n'y a pas d'erreur |
| `error`      | `string`                                            | —            | Texte d'erreur et style de validation                 |
| `size`       | `"sm" \| "md" \| "lg"`                              | `"md"`       | Dimensions du système de conception                   |
| `resize`     | `"none" \| "vertical" \| horizontal" \| "both"`     | `"vertical"` | Comportement de redimensionnement natif               |
| `className`  | `string`                                            | —            | Autres classes Tailwind                               |
| `...props`   | `React.TextareaHTMLAttributes<HTMLTextAreaElement>` | —            | Attributs natifs de textarea                          |

### TypeScript types [#typescript-types]

```ts title="textarea-types.ts"
export type TextareaSize = "sm" | "md" | "lg";
export type TextareaResize = "none" | "vertical" | "horizontal" | "both";

export interface TextareaProps
  extends
    Omit<React.TextareaHTMLAttributes<HTMLTextAreaElement>, "size">,
    VariantProps<typeof textareaVariants> {
  label?: string;
  helperText?: string;
  error?: string;
  size?: TextareaSize;
  resize?: TextareaResize;
}
```

### Accessibilité [#accessibility]

- `label` est connecté à la zone de texte avec `htmlFor`.
- Un id stable est généré avec `React.useId` lorsqu'aucun identifiant n'est fourni.
- `helperText` est connecté avec `aria-describedby`.
- `error` est connecté avec `aria-errormessage`.
- `error` sets `aria-invalid`.
- `error` Le texte a `role="alert"` et est annoncé en direct, même si le domaine est déjà ciblé.
- `required` sets `aria-required`.
- Ne comptez pas sur le texte de l'espace réservé comme seule description accessible.

<Callout title="Règle d'accessibilité">
  Chaque zone de texte doit avoir une étiquette claire. Le texte d'aide et le
  texte d'erreur devraient clarifier la tâche, pas remplacer l'étiquette.

</Callout>

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Textarea doit-il utiliser une étiquette visible ?">
    Oui. Une étiquette visible améliore la convivialité et l’accessibilité. Le texte de l'espace réservé ne doit fournir que des exemples ou des conseils.
  </Accordion>

<Accordion title="Dois-je utiliser Textarea pour les titres ?">
  Habituellement non. Utilisez la saisie pour les titres courts, les noms, les
  limaces, les courriels et les URL.
</Accordion>

<Accordion title="Est-ce que Textarea peut être utilisé dans Sheet ou Dialog ?">
  Oui. Cela fonctionne bien pour les commentaires, les notes et les formulaires
  de rétroaction. Utilisation `resize="none"` si le redimensionnement briserait
  la mise en page de superposition.
</Accordion>

  <Accordion title="Le texte d'aide doit-il rester visible en cas d'erreur ?">
    Dans ce composant, le texte d'erreur remplace le texte d'aide pour garder le retour de champ concentré. Inscrire des exigences permanentes sur l'étiquette ou sur la copie qui l'entoure si elles doivent rester visibles.
  </Accordion>
</Accordions>
