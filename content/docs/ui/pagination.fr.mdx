## Navigation contrôlée pour le contenu paginé [#controlled-navigation-for-paged-content]

Les **Pagination** component fournit des primitives d'interface utilisateur composables pour la navigation dans le contenu paginé.

Utilisez-le pour:

- tableaux de données
- Listes d'administration
- rapports
- factures
- utilisateurs
- projets
- résultats de recherche
- Vues du tableau de bord

La pagination est intentionnelle **idiot**. Il ne possède pas de routage, de récupération, de synchronisation d'URL, de logique de curseur, de logique de taille de page ou d'état de serveur.

La page ou la couche de données possède la logique. L'interface utilisateur rend la navigation.

<Callout title="Idée de base">
  La pagination devrait rendre la navigation de page, pas posséder le modèle de
  données.

</Callout>

### Importation [#import]

```tsx title="pagination-import.tsx"
import { Pagination } from "@pycolors/ui";
```

### Utilisation de base [#basic-usage]

La pagination est composée de petites primitives :

- `Pagination` à l'élément de navigation wrapper
- `PaginationContent` Liste des conteneurs
- `PaginationItem` à l'emballage d'article
- `PaginationLink` pour le contrôle de page
- `PaginationPrevious` / `PaginationNext` Contrôles directionnels
- `PaginationEllipsis` à l'indicateur de débordement compact

```tsx title="pagination-basic-example.tsx"
"use client";

import * as React from "react";
import {
  Pagination,
  PaginationContent,
  PaginationItem,
  PaginationLink,
  PaginationPrevious,
  PaginationNext,
  PaginationEllipsis,
  buildPaginationRange,
} from "@pycolors/ui";

export function PaginationBasicExample() {
  const [page, setPage] = React.useState(1);
  const totalPages = 12;

  const tokens = buildPaginationRange({ page, totalPages });

  return (
    <Pagination>
      <PaginationContent>
        <PaginationItem>
          <PaginationPrevious
            disabled={page === 1}
            onClick={() => setPage((current) => Math.max(1, current - 1))}
          />
        </PaginationItem>

        {tokens.map((token) =>
          token.type === "ellipsis" ? (
            <PaginationItem key={token.key}>
              <PaginationEllipsis />
            </PaginationItem>
          ) : (
            <PaginationItem key={token.value}>
              <PaginationLink
                isActive={token.isActive}
                onClick={() => setPage(token.value)}
              >
                {token.value}
              </PaginationLink>
            </PaginationItem>
          ),
        )}

        <PaginationItem>
          <PaginationNext
            disabled={page === totalPages}
            onClick={() =>
              setPage((current) => Math.min(totalPages, current + 1))
            }
          />
        </PaginationItem>
      </PaginationContent>
    </Pagination>
  );
}
```

### Composition du lien [#link-composition]

`PaginationLink`, `PaginationPrevious`et `PaginationNext` Soutenez le `asChild` modèle de composition. Passer une ancre réelle (ou un cadre) `Link`) comme l'enfant et le contrôle le rend comme élément racine tout en préservant tous les styles, `data-slot`, étiquettes accessibles, et - pour `PaginationPrevious` et `PaginationNext` - l'icône intégrée et le texte visible.

### buildPaginationRange [#buildpaginationrange]

Utilisation `buildPaginationRange` pour générer des tokens de page compacts avec ellipse.

```tsx title="build-pagination-range.ts"
const tokens = buildPaginationRange({
  page,
  totalPages,
});
```

Les tokens retournés peuvent représenter :

- Numéros de page
- Page active
- marqueurs d'ellipse

Cela maintient la logique de rendu propre tout en gardant Pagination contrôlée.

### Utilisations [#usage-patterns]

<Steps>
  <Step>
    #### Conserver l'état de la page en dehors du composant [#keep-page-state-outside-the-component]

    Stocker `page`, `pageSize`et `totalPages` dans la page, le crochet de fonctionnalité ou la couche de données.

</Step>

  <Step>
    #### Désactiver la navigation impossible [#disable-impossible-navigation]

    Désactiver Précédent sur la première page et Suivant sur la dernière page.

</Step>

  <Step>
    #### Utiliser l'ellipse pour les grands nombres de pages [#use-ellipsis-for-large-page-counts]

    Évitez de rendre des dizaines de liens de page. Larges gammes compactes avec ellipses.

</Step>

  <Step>
    #### Synchronisation de l'URL uniquement au niveau de la couche produit [#sync-url-only-at-the-product-layer]

    La synchronisation d'URL appartient à votre page ou couche de routage, pas à la primitive d'interface utilisateur.

</Step>

  <Step>
    #### Paire avec états de chargement et de vide [#pair-with-loading-and-empty-states]

    La pagination doit fonctionner avec la table, les états de chargement, les états vides et les filtres comme un modèle de produit.

</Step>

</Steps>

## Pagination vs défilement infini [#pagination-vs-infinite-scroll]

| Situation                                         | Utilisation                               |
| ------------------------------------------------- | ----------------------------------------- |
| Tableau d'administration                          | Pagination                                |
| Résultats de recherche avec nombre de pages connu | Pagination                                |
| Factures, utilisateurs, abonnements               | Pagination                                |
| Navigation sous forme de flux                     | Défilement infini                         |
| API Cursor uniquement sans concept de page        | Contrôles du curseur au niveau du produit |
| Petit ensemble de données                         | Pas de pagination                         |

<Callout title="Règle de décision">
  Utilisez Pagination lorsque l'utilisateur bénéficie d'une position stable dans
  un ensemble de résultats finis.

</Callout>

## API [#api]

#### Composante [#component]

| Composante           | Désignation                                            |
| -------------------- | ------------------------------------------------------ |
| `Pagination`         | Wrapper `nav` élément avec la sémantique de pagination |
| `PaginationContent`  | Liste des conteneurs                                   |
| `PaginationItem`     | Emballage d'article                                    |
| `PaginationLink`     | Contrôle de page avec état actif                       |
| `PaginationPrevious` | Bouton précédent                                       |
| `PaginationNext`     | Bouton suivant                                         |
| `PaginationEllipsis` | Indicateur de débordement visuel                       |

#### PaginationLink accessoires [#paginationlink-props]

| Prop        | Type      | Par défaut  | Désignation                                                                                     |
| ----------- | --------- | ----------- | ----------------------------------------------------------------------------------------------- |
| `asChild`   | `boolean` | `false`     | Rendu comme une enveloppe de fente; fournir une ancre réelle ou un lien de cadre comme l'enfant |
| `isActive`  | `boolean` | `false`     | Marque la page actuelle                                                                         |
| `size`      | `string`  | `"icon-sm"` | Cartes à tailles de boutons                                                                     |
| `className` | `string`  | —           | Autres classes Tailwind                                                                         |

#### PaginationPrécédent [#paginationprevious-props]

| Prop        | Type      | Par défaut        | Désignation                                                            |
| ----------- | --------- | ----------------- | ---------------------------------------------------------------------- |
| `asChild`   | `boolean` | `false`           | Rendu en tant que wrapper Slot; icône et texte intégrés sont préservés |
| `label`     | `string`  | `"Previous page"` | Étiquette accessible pour les lecteurs d'écran                         |
| `className` | `string`  | —                 | Autres classes Tailwind                                                |

#### PaginationProchains accessoires [#paginationnext-props]

| Prop        | Type      | Par défaut    | Désignation                                                            |
| ----------- | --------- | ------------- | ---------------------------------------------------------------------- |
| `asChild`   | `boolean` | `false`       | Rendu en tant que wrapper Slot; icône et texte intégrés sont préservés |
| `label`     | `string`  | `"Next page"` | Étiquette accessible pour les lecteurs d'écran                         |
| `className` | `string`  | —             | Autres classes Tailwind                                                |

#### Options de buildPaginationRange [#buildpaginationrange-options]

| Variante     | Type     | Désignation           |
| ------------ | -------- | --------------------- |
| `page`       | `number` | Page actuelle         |
| `totalPages` | `number` | Nombre total de pages |

### Accessibilité [#accessibility]

La pagination doit être compréhensible et accessible au clavier.

Directives :

- Utiliser la sémantique `nav` avec étiquetage de pagination
- marquer la page active avec `aria-current="page"`
- garder les boutons clavier accessible
- Désactiver les options Précédent et Suivant en cas d'indisponibilité
- rendre l'ellipse non interactive
- éviter les clics minuscules dans les mises en page denses
- fournir une synchronisation d'URL au niveau du calque de page lorsque la liaison profonde est importante

<Callout title="Règle d'accessibilité">
  Les contrôles de pagination doivent être navigables, compréhensibles et
  prévisibles sans dépendre uniquement de la position visuelle.

</Callout>

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Faut-il synchroniser Pagination avec l'URL ?">
    Souvent oui pour les pages riches en données, mais la synchronisation d'URL appartient à la couche de page ou de route. La pagination devrait rester UI-seulement.
  </Accordion>

<Accordion title="Pagination peut-il fonctionner avec des API basées sur un curseur ?">
  Oui, mais la logique du curseur appartient à la couche de données. Utilisez
  les contrôles Précédent et Suivant si les pages numériques n'existent pas.
</Accordion>

<Accordion title="Quand faut-il cacher la pagination ?">
  Cachez-le lorsqu'il n'y a qu'une seule page, lorsque l'ensemble de données est
  minuscule ou lorsqu'un état vide est affiché.
</Accordion>

  <Accordion title="La taille de la page devrait-elle faire partie de Pagination?">
    Habituellement non. La sélection de taille de page est un contrôle de barre d'outils ou de table. La pagination devrait se concentrer sur la navigation de page.
  </Accordion>
</Accordions>
