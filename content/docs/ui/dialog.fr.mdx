## Tâches modales ciblées [#focused-modal-tasks]

Les **boîte dialogue** component rend une superposition modale pour les tâches ciblées qui nécessitent l'attention de l'utilisateur.

Utilisez-le pour:

- confirmations
- Formes courtes
- Décisions destructrices
- créer ou modifier des flux
- tâches qui ne devraient pas s'éloigner de la page actuelle

Le dialogue est construit sur **Boîte de dialogue Radix** et stylisé avec des tokens PyColors tels que `bg-card`, `border-border`et `text-card-foreground`.

<Callout title="Idée de base">
  La boîte de dialogue est pour les décisions ou les tâches ciblées. Si le flux
  devient long, de navigation ou en plusieurs étapes, utilisez un panneau latéral ou
  une page dédiée.

</Callout>

### Défilement lié [#bounded-scrolling]

Conservez un contenu d'examen plus long à l'intérieur d'une surface délimitée par une fenêtre d'affichage telle que `flex max-h-[80dvh] flex-col overflow-hidden`. Donner l'en-tête et le pied de page `shrink-0`, et mettre `min-h-0 flex-1 overflow-y-auto` dans la région de contenu. Le titre et les actions restent alors visibles pendant que le corps défile.

Donnez à la région scrollable un nom accessible et `tabIndex={0}` afin que les utilisateurs de clavier puissent l'atteindre et le faire défiler. Les [Exemple à long contenu](https://ui.pycolors.io/?path=/story/components-dialog--long-content) démontre cette disposition et vérifie le focus, le défilement et les actions atteignables.

### Utilisations [#usage-patterns]

<Steps>
  <Step>
    #### Déclenchement avec un élément sémantique [#trigger-with-a-semantic-element]

    Utilisation `DialogTrigger asChild` avec a `Button` ou un autre déclencheur sémantique.

</Step>

  <Step>
    #### Fournir un contexte clair [#provide-clear-context]

    Chaque dialogue doit avoir un `DialogTitle` et une utile `DialogDescription`.

</Step>

  <Step>
    #### Gardez le contenu concentré [#keep-the-content-focused]

    Un dialogue doit généralement contenir une tâche, un formulaire ou une décision.

</Step>

  <Step>
    #### Placer les actions dans le pied de page [#place-actions-in-the-footer]

    Gardez annuler et confirmer les actions dans `DialogFooter` pour un placement prévisible.

</Step>

  <Step>
    #### Fermer uniquement lorsque la tâche est terminée ou annulée [#close-only-when-the-task-is-complete-or-canceled]

    Ne fermez pas la boîte de dialogue automatiquement si la soumission échoue. Afficher l'erreur dans le contexte.

</Step>

</Steps>

## Boîte de dialogue vs feuille vs menu déroulant [#dialog-vs-sheet-vs-dropdown-menu]

| Situation                                     | Utilisation     |
| --------------------------------------------- | --------------- |
| Confirmer l'action destructrice               | boîte dialogue  |
| Forme courte                                  | boîte dialogue  |
| Créer ou modifier un petit enregistrement     | boîte dialogue  |
| Filtres avancés                               | Sheet           |
| Flux de travail latéral ou panneau de détails | Sheet           |
| Actions de rangée ou petit menu contextuel    | menu déroulant  |
| Long débit multi-étapes                       | Page ou feuille |

<Callout type="info" title="Règle de décision">
  La boîte de dialogue bloque la page pour une tâche ciblée. Sheet étend la page
  pour les flux de travail latéraux. DropdownMenu expose des actions rapides.

</Callout>

## API [#api]

#### Composants [#components]

| Composante          | Désignation                                                              |
| ------------------- | ------------------------------------------------------------------------ |
| `Dialog`            | Récipient racine                                                         |
| `DialogTrigger`     | Élément déclencheur, généralement avec `asChild`                         |
| `DialogContent`     | Surface modale, superposition et comportement proche                     |
| `DialogHeader`      | Titre et description stack helper                                        |
| `DialogFooter`      | Action Row Helper                                                        |
| `DialogTitle`       | Titre du dialogue accessible                                             |
| `DialogDescription` | Texte d ' appui                                                          |
| `DialogClose`       | Fermez le contrôle, généralement en enveloppant un bouton avec `asChild` |

#### Props [#props]

Les composants de la boîte de dialogue étendent leurs accessoires Radix Dialog respectifs.

```ts title="dialog-props.ts"

React.ComponentPropsWithoutRef<typeof DialogPrimitive.Trigger>;
React.ComponentPropsWithoutRef<typeof DialogPrimitive.Content>;
React.ComponentPropsWithoutRef<typeof DialogPrimitive.Close>;
```

### Accessibilité [#accessibility]

- La boîte de dialogue est construite sur les primitives Radix Dialog.
- La focus est piégée à l'intérieur du dialogue lorsqu'elle est ouverte.
- La focus est restaurée sur le déclencheur lorsque la boîte de dialogue se ferme.
- Escape devrait fermer la boîte de dialogue à moins que le flux ne nécessite une manipulation personnalisée minutieuse.
- Chaque dialogue a besoin d’une `DialogTitle`.
- Utilisation `DialogDescription` pour expliquer la tâche ou le risque.
- Évitez les dialogues imbriqués.
- N'utilisez pas Dialog pour les longs flux de navigation.

<Callout title="Règle d'accessibilité">
  Un dialogue sans titre clair n'est pas un dialogue complet. Le titre donne aux
  utilisateurs de technologies d'assistance le contexte dont ils ont besoin.

</Callout>

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Les formulaires doivent-ils toujours utiliser la boîte de dialogue ?">
    Non. Utilisez la boîte de dialogue pour les formes courtes et ciblées. Utilisez une page ou un panneau latéral pour les formulaires longs, les flux en plusieurs étapes ou les flux de travail qui nécessitent plus d’espace.
  </Accordion>

<Accordion title="La boîte de dialogue peut-elle contenir une table ?">
  Habituellement non. Les tables ont souvent besoin d'espace, de numérisation et
  d'interaction avec les lignes. Utilisez plutôt une page ou un panneau latéral.
</Accordion>

<Accordion title="Les actions destructrices devraient-elles toujours utiliser la boîte de dialogue?">
  Utilisez la boîte de dialogue lorsque l'action est risquée, irréversible ou
  nécessite une confirmation explicite. Pour des actions réversibles, un toast
  avec Undo peut suffire après une interaction plus sûre.
</Accordion>

  <Accordion title="Puis-je masquer le titre visuellement ?">
    Vous pouvez masquer visuellement un titre si la conception l'exige, mais le titre accessible doit toujours exister.
  </Accordion>
</Accordions>
