## Sécuriser les champs de mot de passe pour les flux d'authentification [#secure-password-fields-for-auth-flows]

Les **PasswordInput** component est une entrée spécialisée pour le mot de passe et les champs secrets.

Il se construit sur le dessus de la base **Entrées** composant et ajoute un affichage sécurisé/cacher basculer avec le clavier et le soutien de lecteur d'écran.

Utilisez-le pour:

- Formulaires de connexion
- formulaires d'inscription
- mot de passe reset flux
- changement de mot de passe
- paramètres de sécurité du compte
- Flux d'intégration nécessitant des informations d'identification

<Callout title="Idée de base">
  PasswordInput est pour le texte secret. Il devrait préserver la sémantique des
  mots de passe tout en donnant aux utilisateurs un moyen sûr de vérifier ce
  qu'ils ont tapé.

</Callout>

### Comportement [#behavior]

PasswordInput est contrôlé en interne pour la visibilité.

Elle :

- par défaut à `type="password"`
- bascule entre `password` et `text`
- utilise un bouton sémantique pour la bascule
- Prend en charge l'interaction de la souris et du clavier
- expose l'état accessible à bascule avec `aria-pressed`
- réserve la bonne zone d'icônes pour la visibilité

<Callout type="info" title="Règle de sécurité">
  Révéler le mot de passe doit toujours être une action explicite de
  l'utilisateur. Ne jamais afficher de valeurs secrètes par défaut.

</Callout>

### Utilisations [#usage-patterns]

<Steps>
  <Step>
    #### Utilisez une étiquette claire [#use-a-clear-label]

    Les étiquettes telles que Mot de passe, Mot de passe actuel, Nouveau mot de passe et Confirmer le mot de passe sont directes et prévisibles.

</Step>

  <Step>
    #### Ajouter des exigences à proximité du terrain [#add-requirements-close-to-the-field]

    Utilisez le texte d'aide pour les exigences avant la validation, puis le texte d'erreur lorsque l'utilisateur doit corriger quelque chose.

</Step>

  <Step>
    #### Garder un comportement prévisible [#keep-reveal-behavior-predictable]

    La bascule de révélation ne doit changer que la visibilité, pas la validation, le focus ou la valeur du champ.

</Step>

  <Step>
    #### Valider en dehors du composant [#validate-outside-the-component]

    PasswordInput affiche l'état de validation. Votre schéma, serveur ou couche auth définit les règles.

</Step>

  <Step>
    #### Utiliser l'autocomplétion native [#use-native-autocomplete]

    Ajouter `autoComplete` Valeurs telles que `current-password`, `new-password`ou `one-time-code` le cas échéant.

</Step>

</Steps>

## PasswordInput vs Input [#passwordinput-vs-input]

| Situation                                    | Utilisation                                   |
| -------------------------------------------- | --------------------------------------------- |
| Champ de mot de passe                        | PasswordInput                                 |
| Mot de passe actuel                          | PasswordInput                                 |
| Nouveau mot de passe                         | PasswordInput                                 |
| Confirmer le mot de passe                    | PasswordInput                                 |
| Email, nom, URL, recherche                   | Entrées                                       |
| token secret avec comportement de révélation | PasswordInput ou saisie secrète personnalisée |
| Longue valeur secrète                        | Champ secret textarea-like personnalisé       |

<Callout title="Règle de décision">
  Utilisez PasswordInput lorsque la valeur est secrète et bénéficie d'une
  bascule de visibilité.

</Callout>

## API [#api]

#### Props [#props]

PasswordInput expose la même API que Input, sauf :

- `type` est contrôlé en interne
- `rightIcon` est réservé à la visibilité

| Prop           | Type                   | Par défaut | Désignation                             |
| -------------- | ---------------------- | ---------- | --------------------------------------- |
| `label`        | `string`               | —          | Étiquette accessible au-dessus du champ |
| `helperText`   | `string`               | —          | Texte d'aide sous le champ              |
| `error`        | `string`               | —          | Message d'erreur de validation          |
| `leftIcon`     | `React.ReactNode`      | —          | Icône optionnelle affichée à gauche     |
| `size`         | `"sm" \| "md" \| "lg"` | `"md"`     | Densité visuelle                        |
| `className`    | `string`               | —          | Dépassement du vent arrière             |
| `autoComplete` | `string`               | —          | Indication native autocomplete          |

Tous les autres accessoires d'entrée pris en charge sont transférés.

### TypeScript types [#typescript-types]

```ts title="password-input-types.ts"
import type { InputProps } from "@pycolors/ui";

export interface PasswordInputProps extends Omit<
  InputProps,
  "type" | "rightIcon"
> {}
```

### Accessibilité [#accessibility]

PasswordInput est conçu pour une entrée d'informations d'identification accessible.

Directives :

- La visibilité est un vrai bouton
- Le Toggle devrait exposer `aria-label`
- Le Toggle devrait exposer `aria-pressed`
- Les icônes doivent être décoratives et utilisées `aria-hidden`
- l'entrée conserve la sémantique du mot de passe natif
- Les étiquettes, le texte d'aide et les erreurs suivent
- utiliser de manière appropriée `autoComplete` valeurs
- ne retirez pas les bagues de focus de la bascule ou du champ

Valeurs d'auto-complétion recommandées :

| Contexte                    | `autoComplete`     |
| --------------------------- | ------------------ |
| Mot de passe                | `current-password` |
| Enregistrer le mot de passe | `new-password`     |
| Réinitialiser mot de passe  | `new-password`     |
| Confirmer le mot de passe   | `new-password`     |

<Callout title="Règle d'accessibilité">
  Le contrôle de révélation doit être accessible au clavier et doit annoncer
  clairement si le mot de passe est actuellement affiché ou caché.

</Callout>

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Puis-je passer un rightIcon personnalisé ?">
    Non. `rightIcon` est réservé à la visibilité pour maintenir le comportement prévisible.
  </Accordion>

<Accordion title="PasswordInput doit-il valider la force ?">
  Non. PasswordInput affiche l'état de validation. Les règles de force doivent
  résider dans votre schéma, la couche auth ou la validation du serveur.
</Accordion>

<Accordion title="Le mot de passe doit-il être visible par défaut ?">
  Non. Les mots de passe doivent être masqués par défaut et révélés uniquement
  par une action explicite de l'utilisateur.
</Accordion>

  <Accordion title="Puis-je utiliser PasswordInput pour les clés ou tokens API ?">
    Parfois. Si le secret est court et bénéficie du comportement de révélation, PasswordInput peut fonctionner. Pour les tokens longs, construisez un champ secret dédié.
  </Accordion>
</Accordions>
