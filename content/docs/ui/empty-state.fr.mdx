## Expliquer l'absence valide [#explain-valid-absence]

Les **EmptyState** Un composant représente un état valide où il n'y a pas de données à afficher.

Utilisez-le quand:

- Une liste n'a pas d'éléments
- Une table n'a pas de résultats
- un tableau de bord n'a pas encore de données
- Les filtres ne renvoient rien
- une fonctionnalité n'a pas été configurée
- un utilisateur n'a pas créé son premier objet

EmptyState explique ce qui s'est passé et peut guider l'utilisateur vers l'action suivante.

C'est une **pure UI primitive**Il structure le contenu, pas la logique du produit ou de l’entreprise.

<Callout title="Idée de base">
  Vide n'est pas un échec. EmptyState explique une absence valide et aide
  l'utilisateur à avancer.

</Callout>

### Utilisations [#usage-patterns]

<Steps>
  <Step>
    #### Confirmez que l'état est valide [#confirm-the-state-is-valid]

    Utilisez EmptyState uniquement lorsque la demande a réussi ou que l'absence est attendue.

</Step>

  <Step>
    #### Expliquer pourquoi il est vide [#explain-why-it-is-empty]

    Le titre doit nommer l'État. La description devrait expliquer ce que cela signifie.

</Step>

  <Step>
    #### Proposer l'étape suivante quand cela est utile [#offer-the-next-step-when-useful]

    Ajoutez une action lorsque l'utilisateur peut créer, inviter, réinitialiser des filtres ou configurer quelque chose.

</Step>

  <Step>
    #### Correspond à la surface environnante [#match-the-surrounding-surface]

    Utilisez EmptyState dans une carte, un tableau ou une section en fonction de la structure de la page.

</Step>

  <Step>
    #### Gardez la logique du produit à l'extérieur [#keep-product-logic-outside]

    EmptyState ne décide pas de ce qui se passe ensuite. La page ou la fonctionnalité possède ce comportement.

</Step>

</Steps>

## Skeleton vs Alert [#emptystate-vs-skeleton-vs-alert]

| Situation                                           | Utilisation                    |
| --------------------------------------------------- | ------------------------------ |
| Les données sont en cours de chargement             | Squelette                      |
| Demande réussie mais il n'y a pas de données        | EmptyState                     |
| La demande a échoué                                 | Alerte                         |
| L'utilisateur doit confirmer une action             | boîte dialogue                 |
| L'utilisateur a besoin d'un flux de travail latéral | Sheet                          |
| L'intégration nécessite plusieurs étapes            | Interface d'intégration dédiée |

<Callout type="info" title="Règle de décision">
  EmptyState explique l'absence valide. Le squelette représente le chargement.
  L'alerte communique l'échec.

</Callout>

## API [#api]

#### Props [#props]

| Prop          | Type              | Requis | Désignation                                |
| ------------- | ----------------- | ------ | ------------------------------------------ |
| `title`       | `string`          | Oui    | Message principal expliquant l'état vide   |
| `description` | `string`          | Non    | Contexte supplémentaire pour l'état vide   |
| `action`      | `React.ReactNode` | Non    | Action facultative                         |
| `icon`        | `React.ReactNode` | Non    | Icône ou illustration décorative en option |
| `className`   | `string`          | Non    | Autres classes Tailwind                    |

EmptyState accepte aussi le code HTML standard `div` props.

```ts title="empty-state-props.ts"
React.HTMLAttributes<HTMLDivElement>;
```

### TypeScript types [#typescript-types]

```ts title="empty-state-types.ts"
export interface EmptyStateProps extends React.HTMLAttributes<HTMLDivElement> {
  title: string;
  description?: string;
  action?: React.ReactNode;
  icon?: React.ReactNode;
}
```

### Accessibilité [#accessibility]

EmptyState doit être lisible et compréhensible sans se fier aux icônes.

Directives :

- garder le titre clair et descriptif
- garder la signification icon-only en dehors de l'icône
- marquer les icônes décoratives avec `aria-hidden="true"`
- ne forcez pas la focus lorsqu'un état vide apparaît
- Les actions doivent être accessibles au clavier
- n'utilisez pas EmptyState pour annoncer des erreurs
- use Alerte en cas de défaillances et de problèmes de blocage

<Callout title="Règle d'accessibilité">
  Les états vides doivent s'expliquer par le texte. Les icônes peuvent soutenir
  le message, mais elles ne devraient pas porter le seul sens.

</Callout>

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Est-ce que EmptyState devrait être utilisé pour les erreurs ?">
    Non. Utilisez Alerte pour les erreurs. EmptyState est pour une absence valide, pas un échec.
  </Accordion>

<Accordion title="Est-ce que EmptyState devrait toujours avoir une action ?">
  Non. Ajoutez une action uniquement lorsqu'il y a une prochaine étape claire,
  telle que la création d'un élément ou l'effacement des filtres.
</Accordion>

<Accordion title="EmptyState peut-il être utilisé dans les tables ?">
  Oui. Placez-le à l'intérieur d'un `TableCell` avec le bon `colSpan`.
</Accordion>

  <Accordion title="Est-ce que EmptyState doit contenir une logique de produit ?">
    Non. EmptyState rend la structure. La page ou la fonctionnalité détermine ce que l'action fait.
  </Accordion>
</Accordions>
