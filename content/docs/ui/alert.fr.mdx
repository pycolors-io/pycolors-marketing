## Rétroaction en ligne pour les états de produits importants [#inline-feedback-for-important-product-states]

Les **Alerte** Le composant communique des informations importantes directement à l'intérieur de l'interface.

Utilisez-le pour:

- Avis neutres
- résultats de validation
- Confirmations de succès
- avertissements
- Erreurs de blocage
- messages système

Contrairement aux toasts, les alertes sont **inline et persistant**. Ils restent visibles dans le contexte jusqu'à ce que l'utilisateur comprenne ou résolve l'état.

<Callout title="Idée de base">
  Les alertes sont pour les messages qui appartiennent à la page. Les toasts
  sont des commentaires temporaires.

</Callout>

### Importation [#import]


### Variantes disponibles [#available-variants]

| Variante      | Objet                                                              |
| ------------- | ------------------------------------------------------------------ |
| `default`     | Information neutre                                                 |
| `info`        | Information neutre, actuellement alignée avec la valeur par défaut |
| `success`     | Confirmation ou rétroaction positive                               |
| `warning`     | Risque ou attention requise                                        |
| `destructive` | Erreur ou message critique                                         |

<Callout type="info" title="Comportement du token">
  `default` et `info` partager intentionnellement le même langage visuel dans le
  jeu de tokens v1 actuel.

</Callout>

### Annonces avec ariaLive [#announcements-with-arialive]

Les `ariaLive` prop contrôle la façon dont les technologies d'assistance annoncent les mises à jour.

| Valeur      | Rôle     | Utilisation pour                                  |
| ----------- | -------- | ------------------------------------------------- |
| `polite`    | `status` | Mises à jour non bloquantes                       |
| `assertive` | `alert`  | Erreurs critiques                                 |
| `off`       | néant    | Messages statiques qui n'ont pas besoin d'annonce |

Le résultat `role` et `aria-live` sont déterministes : elles sont toujours dérivées de `ariaLive` et avoir préséance sur tout natif `role` ou `aria-live` valeur passée à travers le reste des accessoires du composant.

  Utilisation `assertive` Seulement pour les erreurs urgentes. L'utilisation

  utilisateurs de lecteurs d'écran.

</Callout>

## Alerte vs Toast [#alert-vs-toast]

| Situation                                      | Utilisation |
| ---------------------------------------------- | ----------- |
| Erreur de page de blocage                      | Alerte      |
| Résultat de validation au niveau du formulaire | Alerte      |
| Avis persistant important                      | Alerte      |
| Confirmation de sauvegarde temporaire          | Toast       |
| Mise à jour d'arrière-plan non bloquante       | Toast       |
| Annuler ou réessayer après la mutation         | Toast       |

<Callout title="Règle de décision">
  Si l'utilisateur a besoin du message pour terminer la tâche, utilisez Alerte.
  Si le message est une confirmation temporaire, utilisez Toast.

</Callout>

## API [#api]

| Prop        | Type                               | Par défaut  | Désignation                         |
| ----------- | ---------------------------------- | ----------- | ----------------------------------- |
| `variant`   | `AlertVariant`                     | `"default"` | sémantique visuelle                 |
| `ariaLive`  | `"off" \| "polite" \| "assertive"` | `"polite"`  | Comportement d'annonce d'assistance |
| `className` | `string`                           | —           | Classes Tailwind personnalisées     |

Les composants d'alerte étendent les props HTML standard :

```ts title="alert-types.ts"
React.HTMLAttributes<HTMLDivElement>;
```

### TypeScript types [#typescript-types]

```ts title="alert-types.ts"
export type AlertVariant = NonNullable<AlertProps["variant"]>;

export interface AlertProps
  extends
    React.HTMLAttributes<HTMLDivElement>,
    VariantProps<typeof alertVariants> {
  ariaLive?: "off" | "polite" | "assertive";
}
```

### Accessibilité [#accessibility]

- `ariaLive="polite"` renders `role="status"`.
- `ariaLive="assertive"` renders `role="alert"`.
- `ariaLive="off"` supprime les annonces de live-region.
- Le calcul `role` et `aria-live` ne peut pas être remplacé silencieusement par d'autres accessoires; `ariaLive` C’est la seule source de vérité.
- Ne vous fiez pas uniquement à la couleur pour communiquer du sens.
- Les indicateurs décoratifs doivent utiliser `aria-hidden="true"`.
- Gardez la copie d'alerte claire, courte et exploitable.

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Les messages de réussite doivent-ils utiliser Alert ou Toast?">
    Utilisez Alerte lorsque la confirmation doit rester visible dans le contexte. Utilisez Toast pour des confirmations de courte durée après des actions non bloquantes.
  </Accordion>

<Accordion title="Est-ce que chaque alerte destructive doit s’affirmer ?">
  Non. Utilisation `assertive` uniquement lorsque le message est urgent et que
  l'utilisateur doit le savoir immédiatement.
</Accordion>

<Accordion title="Une alerte peut-elle contenir des actions ?">
  Oui, mais gardez les actions secondaires et concentrées. Si le flux devient
  complexe, utilisez un formulaire dédié, une section de dialogue ou une section
  de page.
</Accordion>

  <Accordion title="Les icônes ne devraient-elles communiquer que du sens ?">
    Non. Les icônes devraient renforcer le sens. Le texte doit expliquer le message.
  </Accordion>
</Accordions>
