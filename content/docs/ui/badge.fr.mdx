## Métadonnées compactes pour les interfaces produits [#compact-metadata-for-product-interfaces]

Les **Badge** component est une primitive compacte et non interactive utilisée pour afficher de courtes informations.

Utilisez-le pour:

- état
- catégorie
- nombre
- étiquette du plan
- métadonnées
- état du produit
- Disponibilité des fonctionnalités

Les badges sont légers, sémantiques et alignés avec les tokens du système de conception PyColors.

Ils sont conçus pour **métadonnées**Pas des actions.

<Callout title="Idée de base">
  Un badge communique l'état ou le contexte. Il ne doit pas remplacer un bouton.

</Callout>

### Variantes disponibles [#available-variants]

| Variante      | Objet                                                                  |
| ------------- | ---------------------------------------------------------------------- |
| `default`     | Étiquette primaire ou neutre                                           |
| `secondary`   | Informations complémentaires                                           |
| `muted`       | Métadonnées de faible importance                                       |
| `outline`     | Étiquette neutre bordée                                                |
| `success`     | État positif ou terminé                                                |
| `warning`     | Précaution ou attention requise                                        |
| `destructive` | Erreur ou état critique                                                |
| `info`        | Statut informationnel - sémantique neutre, utilise des tokens de carte |

<Callout type="info" title="Règle de conception">
  Préférez `muted` et `outline` pour les métadonnées. Réserve des variantes
  d'état sémantique pour les états de produit réels.

</Callout>

Les badges peuvent inclure une icône de gauche lorsque l'icône renforce le statut, le type ou la catégorie.

  Les icônes devraient renforcer le sens. Le texte doit encore expliquer l'état.

</Callout>

  Utilisez les icônes de gauche pour l'état ou l'identité. Utilisez les bonnes

</Callout>

Utilisation `asChild` quand le badge doit être rendu comme un autre élément sémantique.

<Callout title="Règle d'interaction">
  Utilisez uniquement des badges interactifs lorsque l'élément sous-jacent est
  sémantique, comme une ancre ou un bouton. Si cela déclenche une action
  importante, utilisez le bouton à la place.

</Callout>

## Badge vs Bouton vs Alerte [#badge-vs-button-vs-alert]

| Situation                                                   | Utilisation |
| ----------------------------------------------------------- | ----------- |
| Afficher un petit statut                                    | Badge       |
| Afficher une étiquette de catégorie ou de plan              | Badge       |
| Déclencher une action                                       | Bouton      |
| Afficher des commentaires ou des avertissements persistants | Alerte      |
| Confirmer l'action temporaire en arrière-plan               | Toast       |

<Callout title="Règle de décision">
  Le badge communique le contexte. Le bouton déclenche l'intention. Alert
  explique les commentaires importants.

</Callout>

| Prop        | Type           | Par défaut  | Désignation             |

### Accessibilité [#accessibility]

- Les badges ne sont pas interactifs par défaut.
- N’utilisez pas un badge comme bouton.
- Ne vous fiez pas uniquement à la couleur pour transmettre du sens.
- Les icônes doivent être complémentaires, pas le seul indicateur.
- Utilisation `aria-hidden="true"` pour les icônes décoratives.
- Lorsqu’il est interactif, utilisez `asChild` avec un élément sémantique tel que `a` ou `button`.
- `success` et `warning` Utilisation dédiée `--success-foreground` / `--warning-foreground` tokens de conception (voir `@pycolors/tokens`) réglé pour rencontrer le contraste WCAG AA contre leurs arrière-plans respectifs - ne substituez pas une couleur de texte différente sur ces deux variantes.
- `info` utilise des tokens de cartes sémantiques existants; le contraste dépend du thème et doit satisfaire aux mêmes exigences d'accessibilité que les autres variantes de Badge.

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Un badge peut-il être cliquable ?">
    Oui, mais seulement lorsqu'il est rendu avec un élément sémantique `asChild`. S'il effectue une action principale, utilisez le bouton à la place.
  </Accordion>

<Accordion title="Est-ce que chaque statut devrait utiliser un badge de couleur?">
  Non. Utilisez la couleur sémantique uniquement lorsque l'état a besoin d'être
  accentué. Pour les métadonnées de faible priorité, préférez `muted` ou
  `outline`.
</Accordion>

<Accordion title="Les badges peuvent-ils inclure des icônes ?">
  Oui. Les icônes peuvent renforcer le sens, mais le texte doit toujours
  communiquer l'état.
</Accordion>

<Accordion title="Les icônes doivent-elles apparaître à gauche ou à droite ?">
  Utilisez les icônes de gauche pour l'état, l'identité ou la catégorie.
  Utilisez les bonnes icônes pour la direction, la continuation ou le contexte
  lié.
</Accordion>

  <Accordion title="Combien de badges une carte doit-elle avoir ?">
    Utilisez le moins possible. Les badges devraient clarifier l'interface, pas la décorer.
  </Accordion>
</Accordions>
