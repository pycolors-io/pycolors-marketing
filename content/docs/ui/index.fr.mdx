## Exemples de composants interactifs [#interactive-component-examples]

Ouvrir [PyColors UI Explorer](https://ui.pycolors.io) pour essayer les états des composants et les interactions du clavier dans les thèmes clairs et sombres. Chaque page de composant renvoie directement à son exemple.

Pour mettre en place des exemples dans votre propre application, suivez le [guide du consommateur Storybook](/docs/ui/storybook). Vous pouvez également essayer un [Aperçu complet de l'interface](/ui#ui-preview) ou créer une palette dans [Theme Builder](/tools/theme-builder).

## Règles de composition [#composition-rules]

Gardez les pièces petites et connectez-les dans votre application:

- **Utilisez des tokens sémantiques.** Utilitaires comme `bg-card`, `text-muted-foreground`et `border-border` Gardez les composants cohérents entre les thèmes.
- **Composez un écran à partir de primitives.** Combinez les champs, les boutons, les cartes et les commentaires autour d'une tâche.
- **Gardez la logique du produit dans votre application.** Le routage, la récupération de données, l'authentification et la facturation restent des responsabilités de l'application.

  <Accordion title="Contribuer aux exemples de composants" id="maintaining-examples">

Les contributeurs peuvent exécuter Storybook à partir de la racine du référentiel :

```bash
pnpm --filter @pycolors/ui storybook
```

Des exemples canoniques vivent dans `packages/ui/stories/components/<family>.stories.tsx`. Le public `src/index.ts` Le baril reste la source de vérité pour les familles soutenues. Les fondations démontrent des tokens existants; les compositions sont de petits exemples synthétiques. La navigation locale commande les fondations, les composants, puis les compositions.

Lorsqu'un élément public ou un état significatif change :

1. Mettre à jour son module de famille dactylographié avec un `components-<family>` ID, histoire stable exports, a `Default`une description utile et son lien Fumadocs. Importer par `../../src/index.js`, jamais le fichier interne d'un composant.
2. Exposer uniquement les args/contrôles supportés. Les exemples contrôlés possèdent leur propre état; garder les étiquettes, la sémantique native / Radix, les tokens et les deux thèmes intacts.
3. Mettez à jour les tests des composants correspondants et la page Fumadocs lorsque le comportement change. Exécuter `pnpm --filter @pycolors/ui verify`, `pnpm check:ui-package`et `pnpm --filter pycolors-marketing types:check` pour les changements de documentation.
4. Installez Chromium avec `pnpm --filter @pycolors/ui test:storybook:install`, puis courir `pnpm --filter @pycolors/ui test:storybook` pour les interactions, les scans d'accessibilité, les vérifications lumière/obscurité et desktop/mobile. Vérifiez les ID d'histoire générés séparément. Les contrôles automatisés ne remplacent pas la technologie d'assistance et l'examen visuel; la configuration, la sélection et les diagnostics sont dans le guide de l'histoire.
5. Préserver les anciens identifiants via des entrées de compatibilité de rendu partagé lors de la migration des liens. Le registre des migrations et les règles de dépréciation vivent dans `packages/ui/stories/README.md`; le module legacy ne contient pas de nouveaux exemples.

Les modifications story-only n'ont pas besoin d'une version de paquet. Les modifications API/comportement publiques conservent leurs exigences normales en matière de Changeset, de test et de documentation. Les stories publiques ne doivent contenir que des primitives et des fixtures publiques : pas de source Pro, d'importations privées, d'identifiants ou de données client. Voir `packages/ui/stories/README.md` dans le dépôt pour les conventions de configuration des contributeurs et d'ID d'histoire.
