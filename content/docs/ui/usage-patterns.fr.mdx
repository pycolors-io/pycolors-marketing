## Utiliser les primitives comme blocs de construction de produits [#use-primitives-as-product-building-blocks]

Les primitives PyColors UI sont intentionnellement petites. Ils vous donnent des pièces accessibles et basées sur des tokens pour les interfaces SaaS, mais votre application possède l’état du produit, la récupération des données, le routage, la validation et les règles métier.

Utilisez cette page lorsque vous savez quels composants vous avez besoin et que vous voulez les composer dans un écran réel sans lire la source du paquet.

<Callout title="Idée de base">
  Importer des primitives publiques depuis `@pycolors/ui`, conservez la logique
  du produit dans votre application et composez le comportement de la page, de
  la fonctionnalité ou du calque de motif.

</Callout>

## Essayez de copier les exemples [#try-and-copy-the-examples]

Complete [Installation de l'interface utilisateur](/docs/ui/installation) tout d'abord, y compris le scan du paquet Tailwind et le token CSS. Chaque **Source** onglet ci-dessous comprend le fichier complet utilisé par son **Aperçu**. Copiez le fichier dans votre application; utilisez le bouton de copie de bloc de code ou sélectionnez le code manuellement.

La boîte de dialogue et Pagination utilisent l'option `lucide-react` Pair pour leurs icônes. Installez-le si votre application ne le fournit pas déjà :

```bash
pnpm add lucide-react
```

Les quatre exemples interactifs gardent l'état en mémoire. La mise à jour les réinitialise ; aucune donnée n'est envoyée, stockée à distance ou utilisée pour modifier un compte. Le formulaire affiche la validation, la boîte de dialogue engage ou annule une modification, le tableau change de pages et le toast ne s'ouvre qu'après une action.

Par exemple, enregistrez la source de formulaire comme `components/notification-settings.tsx` et le rendre à partir d'une page Next.js :

```tsx title="app/page.tsx"
import { NotificationSettings } from "../components/notification-settings";

export default function SettingsPage() {
  return <NotificationSettings />;
}
```

La page peut rester un composant de serveur. Chaque exemple interactif déclare ses propres limites client et importe uniquement React et le public `@pycolors/ui` point d'entrée. Connectez la persistance de votre application et la validation côté serveur séparément.

## Règles d'utilisation requises [#required-usage-rules]

Ces règles font partie du contrat d'utilisation pris en charge.

- Importation à partir du point d'entrée du paquet public: `@pycolors/ui`.
- Conserver `@pycolors/ui` primitives app-agnostic. Ne mettez pas d'auth, de facturation, de routage ou de décisions spécifiques au produit dans des composants d'interface utilisateur partagés.
- Préserver la sémantique native : boutons pour les actions, liens pour la navigation, étiquettes pour les contrôles de formulaire et balisage de table pour les données tabulaires.
- Ajoutez une limite client uniquement lorsque votre application utilise le comportement du navigateur, l'état local, les gestionnaires d'événements ou la composition interactive Radix.
- Utilisez les documents de composants existants pour les accessoires et les variantes exacts avant d'inventer un emballage local.
- Gardez les responsabilités d'accessibilité visibles lorsque vous composez des superpositions, des formulaires, des commentaires et des vues de données denses.

## Valeurs par défaut recommandées [#recommended-defaults]

Ces valeurs par défaut ne sont pas des exigences strictes, mais elles maintiennent les surfaces du produit cohérentes.

- Débuter avec `Button`, `Input`, `Card`, `Alert`et `Table` avant d'ajouter des abstractions locales.
- Utilisation `Dialog` pour des décisions ciblées et des formes courtes.
- Utilisation `Sheet` pour les workflows latéraux qui devraient garder le contexte de la page visible.
- Utilisation `Tabs` pour la commutation entre les panneaux connexes, pas pour la navigation primaire.
- Utilisation `Toast` pour un feedback non bloquant après les actions.
- Utilisation `Alert` pour la rétroaction inline persistante qui affecte la tâche en cours.
- Utilisation `Pagination` lorsque l'utilisateur a besoin d'une position de page stable et d'un enregistrement prévisible.

## Utilisation des composants serveur et client [#server-and-client-component-usage]

De nombreuses primitives PyColors peuvent être composées dans une page rendue par le serveur lorsque vous passez du contenu statique et aucun gestionnaire d'événements. Dès que votre fichier possède un état, des effets ou des gestionnaires d'événements, déplacez cette composition vers un petit composant client.

```tsx title="server-safe-summary-card.tsx"
import { Alert, AlertDescription, AlertTitle, Button } from "@pycolors/ui";

export function BillingSummary() {
  return (
    <section className="space-y-4">
      <Alert>
        <AlertTitle>Plan active</AlertTitle>
        <AlertDescription>
          Your workspace is covered until the next renewal.
        </AlertDescription>
      </Alert>

      <Button asChild>
        <a href="/settings/billing">Manage billing</a>
      </Button>
    </section>
  );
}
```

Utilisez une limite client pour la composition pilotée par les événements.

Attentes en matière d'accessibilité :

- Chaque contrôle de formulaire nécessite une étiquette visible ou un nom accessible équivalent.
- Les erreurs de validation doivent être du texte, pas seulement de la couleur.
- Les contrôles désactivés doivent toujours indiquer pourquoi l'action n'est pas disponible lorsque cette raison est importante pour le flux de travail.

## Revêtements [#overlays]

Choisissez les superpositions en fonction du travail.

| Besoin                                                                | Primitif       |
| --------------------------------------------------------------------- | -------------- |
| Confirmer ou terminer une tâche ciblée                                | `Dialog`       |
| Travaillez dans un panneau latéral sans perdre le contexte de la page | `Sheet`        |
| Choisissez une action de ligne ou de menu compacte                    | `DropdownMenu` |

```tsx title="filters-sheet.tsx"
"use client";

import {
  Button,
  Checkbox,
  CheckboxField,
  CheckboxLabel,
  Sheet,
  SheetContent,
  SheetDescription,
  SheetHeader,
  SheetTitle,
  SheetTrigger,
} from "@pycolors/ui";

export function FiltersSheet() {
  return (
    <Sheet>
      <SheetTrigger asChild>
        <Button variant="outline">Filters</Button>
      </SheetTrigger>

      <SheetContent side="right">
        <SheetHeader>
          <SheetTitle>Filter customers</SheetTitle>
          <SheetDescription>
            Narrow the table without leaving the current view.
          </SheetDescription>
        </SheetHeader>

        <div className="mt-6 space-y-3">
          <CheckboxField>
            <Checkbox id="trialing" />
            <CheckboxLabel htmlFor="trialing">Trialing</CheckboxLabel>
          </CheckboxField>
          <CheckboxField>
            <Checkbox id="past-due" />
            <CheckboxLabel htmlFor="past-due">Past due</CheckboxLabel>
          </CheckboxField>
        </div>
      </SheetContent>
    </Sheet>
  );
}
```

Incluez les attentes en matière d’accessibilité :

- Le déclencheur doit avoir un texte clair ou une étiquette accessible.
- Les titres de dialogue et de feuille doivent décrire la tâche.
- Le comportement d'évasion et de retour de la focus doit rester intact.
- Ne placez pas de longs flux de travail en plusieurs étapes dans un modal lorsqu’une page serait plus claire.

## Sections de produits avec onglets [#product-sections-with-tabs]

Utilisation `Tabs` pour basculer entre les panneaux connexes à l'intérieur de la même page.

```tsx title="settings-tabs.tsx"
import { Tabs, TabsContent, TabsList, TabsTrigger } from "@pycolors/ui";

export function SettingsTabs() {
  return (
    <Tabs defaultValue="profile">
      <TabsList aria-label="Settings sections">
        <TabsTrigger value="profile">Profile</TabsTrigger>
        <TabsTrigger value="billing">Billing</TabsTrigger>
        <TabsTrigger value="security">Security</TabsTrigger>
      </TabsList>

      <TabsContent value="profile">Profile form</TabsContent>
      <TabsContent value="billing">Billing controls</TabsContent>
      <TabsContent value="security">Security settings</TabsContent>
    </Tabs>
  );
}
```

Utilisez des liens de navigation au lieu d'onglets lorsque la destination est une autre route, une page bookmarkable ou une architecture d'informations primaires.

- Gardez les en-têtes de colonne significatifs.
- Utilisez des légendes ou des en-têtes à proximité lorsque le but de la table n'est pas évident.
- Gardez les contrôles de pagination utilisables au clavier et étiquetés pour la collection qu'ils contrôlent.

## Motifs de rétroaction [#feedback-patterns]

Utilisez la rétroaction en ligne lorsque le message affecte la surface actuelle. Utilisez les commentaires de toast lorsque le message confirme une action terminée sans bloquer l'utilisateur.

```tsx title="inline-feedback.tsx"
import { Alert, AlertDescription, AlertTitle } from "@pycolors/ui";

export function PaymentIssueAlert() {
  return (
    <Alert variant="destructive">
      <AlertTitle>Payment failed</AlertTitle>
      <AlertDescription>
        Update your payment method to keep the workspace active.
      </AlertDescription>
    </Alert>
  );
}
```

Activez le bouton pour simuler un enregistrement réussi, rejetez la notification et déclenchez-la à nouveau. Relâcher le focus sur le trigger. Cet exemple autonome possède un fournisseur et une fenêtre d'affichage; réutilisez votre fournisseur existant lors de son intégration.
