## Surfaces structurées pour interface produit [#structured-surfaces-for-product-ui]

Les **Carte** Component est une surface fondamentale utilisée pour regrouper le contenu, les actions et les métadonnées associés.

Utilisez-le pour:

- tuiles de tableau de bord
- blocs de tarification
- panneaux de réglages
- résumés de facturation
- caractéristiques des cartes
- liste des éléments
- états vides
- sections de compte
- surfaces des produits

La carte est construite sur des tokens sémantiques tels que `bg-card`, `border-border`et `text-card-foreground`, de sorte qu'il reste cohérent à travers des thèmes clairs et sombres.

<Callout title="Idée de base">
  La carte crée la structure. Utilisez-le pour regrouper du contenu
  significatif, pas comme décoration.

</Callout>


### Variantes disponibles [#available-variants]

| Variante      | Objet                                                         |
| ------------- | ------------------------------------------------------------- |
| `default`     | Surface principale utilisant `bg-card`                        |
| `muted`       | Surface secondaire utilisant un fond plus doux                |
| `transparent` | Conteneur de mise en page uniquement sans arrière-plan rempli |

<Callout type="info" title="Variante de règle">
  Utilisation `default` pour les surfaces primaires, `muted` pour les groupes
  secondaires, et `transparent` Lorsque vous n’avez besoin que de structure.

</Callout>

### Cartes interactives [#interactive-cards]

`interactive` ajoute des affordances visuelles uniquement - curseur, arrière-plan plan et un anneau focus-visible. La carte n'attache jamais son propre clic ou la manipulation du clavier, donc une carte interactive doit composer `asChild` avec un réel `<button>` pour une action ou un réel `<a>`/`Link` pour la navigation. Ces éléments fournissent le clavier correct, la focus et le clic sémantique nativement - Card n'a pas besoin (et ne doit pas) les recréer.

<Tabs items={["Aperçu", "Code"]}>
  <Tab value="Aperçu">

      <div className="grid gap-4 sm:grid-cols-2">
        <Card asChild interactive>
          <button type="button" className="block w-full text-left">

              <CardTitle>Sélectionnez un plan</CardTitle>
              <CardDescription>Un bouton réel donne le clic natif et le comportement du clavier gratuitement.</CardDescription>
            </CardHeader>
          </button>
        </Card>

              <CardTitle>Voir les tarifs</CardTitle>

<Callout type="info" title="Support clavier">
  `interactive` Ne jamais ajouter `role`, `tabIndex`, ou la manipulation du
  clavier - il est visuel seulement. A nue `Card interactive` avec aucun
  `asChild` target n'est pas accessible au clavier ou au lecteur d'écran.
  Toujours composer `asChild` avec un réel `button` pour des actions ou un réel
  `a`/`Link` pour la navigation.

</Callout>

### Composition [#composition]

Une carte suit généralement cette structure:

```tsx title="card-anatomy.tsx"
<Card>
  <CardHeader>
    <CardTitle>Title</CardTitle>
    <CardDescription>Description</CardDescription>
  </CardHeader>

  <CardContent>Content</CardContent>

  <CardFooter>Actions</CardFooter>
</Card>
```

Utilisez chaque slot intentionnellement :

| Emplacement       | Objet                                             |
| ----------------- | ------------------------------------------------- |
| `CardHeader`      | Présente la surface                               |
| `CardTitle`       | Nomme le contenu groupé                           |
| `CardDescription` | Ajoute un contexte court                          |
| `CardContent`     | Contient le corps principal                       |
| `CardFooter`      | Détient des actions ou des métadonnées de support |

    Utilisation `asChild` avec un véritable lien pour les cartes de navigation.

</Step>

## Carte vs section vs liste [#card-vs-section-vs-list-item]

| Situation                               | Utilisation               |
| --------------------------------------- | ------------------------- |
| Contenu groupé avec une surface visible | Carte                     |
| Grande section de page avec des titres  | Chapitre                  |
| Rangées compactes répétées              | Élément de liste          |
| Tuile de navigation                     | Carte avec `asChild` lien |
| KPI ou métrique                         | Carte                     |
| Données du tableau                      | Tableau                   |
| Statut temporaire ou erreur             | Alerte ou état vide       |

<Callout title="Règle de décision">
  Utilisez Card lorsque la surface aide les utilisateurs à comprendre le
  regroupement, la priorité ou l'interaction.

</Callout>

## API [#api]

#### Composants [#components]

| Composante        | Désignation                            |
| ----------------- | -------------------------------------- |
| `Card`            | Surface des racines                    |
| `CardHeader`      | Zone de tête                           |
| `CardTitle`       | Titre de la carte                      |
| `CardDescription` | Texte d ' appui                        |
| `CardContent`     | Zone de contenu principale             |
| `CardFooter`      | Actions de pied de page ou métadonnées |

#### Card props [#card-props]

| Prop          | Type          | Par défaut  | Désignation                                    |
| ------------- | ------------- | ----------- | ---------------------------------------------- |
| `variant`     | `CardVariant` | `"default"` | Style de surface                               |
| `interactive` | `boolean`     | `false`     | Ajoute des commentaires hover et focus-visible |
| `asChild`     | `boolean`     | `false`     | Rendu via Radix Slot                           |
| `className`   | `string`      | —           | Autres classes Tailwind                        |

La carte étend le standard HTML `div` props.

```ts title="card-props.ts"
React.HTMLAttributes<HTMLDivElement>;
```

### Accessibilité [#accessibility]

Directives :

- utiliser des en-têtes significatifs à l'intérieur des cartes lorsqu'elles introduisent une section
- `interactive` ajoute seulement des affordances visuelles (curseur, hover, anneau de focus-visible) - il n'ajoute jamais `role`, `tabIndex`, ou manipulation du clavier
- a nues `Card interactive` avec aucun `asChild` target n'est pas accessible au clavier ou au lecteur d'écran - il s'agit uniquement de style
- utilisation `asChild` avec un réel `a`/`Link` pour les cartes de navigation
- utilisation `asChild` avec un réel `button` pour les cartes d'action
- `asChild interactive` emballer un élément non focalisable (par exemple un `div`) n'est pas valide - l'enfant sloté doit être un élément interactif réel
- éviter les contrôles interactifs imbriqués dans une carte cliquable
- garder les états de focus visibles pour les cartes interactives
- ne pas rendre une carte interactive uniquement pour la décoration visuelle

<Callout title="Règle d'accessibilité">
  Carte ne synthétise jamais le clavier ou le comportement de focus. Une
  carte interactive n'est vraiment accessible que lorsque `asChild` Envelopper
  un réel `a`/`Link` (navigation) ou `button` (action) - ces éléments
  fournissent un clavier correct, une focus et une sémantique de clic
  nativement.

</Callout>

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Chaque groupe de contenu devrait-il être une carte?">
    Non. Utilisez la carte lorsque la surface améliore le regroupement, la hiérarchie ou l'interaction. Les sections simples n'ont pas toujours besoin d'une surface bordée.
  </Accordion>

<Accordion title="Une carte peut-elle être cliquable ?">
  Oui. Utilisation `asChild` avec un lien ou un bouton sémantique et activer
  `interactive` pour le feedback visuel.
</Accordion>

<Accordion title="Quand dois-je utiliser la variante en sourdine?">
  Utilisation `muted` pour les surfaces secondaires, les dispositions denses ou
  les panneaux de support où la carte par défaut est trop forte visuellement.
</Accordion>

  <Accordion title="Les cartes peuvent-elles contenir des formulaires ?">
    Oui. Les cartes fonctionnent bien pour les formulaires de paramètres. Gardez les étiquettes, la validation et les actions claires.
  </Accordion>
</Accordions>
