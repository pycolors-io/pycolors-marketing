## Champs de texte fiables pour les formulaires de produits [#reliable-text-fields-for-product-forms]

Les **Entrées** component est un contrôle de formulaire fondamental dans PyColors UI.

Utilisez-le pour:

- Formulaires de connexion
- champs de recherche
- formulaires de paramètres
- détails de facturation
- champs de profil
- Filtres d'administration
- Flux de création de produits
- Formulaires pilotés par validation

L'entrée est conçue pour être accessible par défaut, sensible au thème et suffisamment flexible pour des champs simples ou des mises en page de formulaire de production.

Il soutient:

- étiquettes
- Texte d'aide
- Erreurs de validation
- Icônes gauche et droite
- Variantes de taille
- support clavier et lecteur d'écran

<Callout title="Idée de base">
  Input collecte les données des utilisateurs. Les règles de validation doivent
  résider dans votre calque de formulaire ou de schéma, et non dans la primitive
  visuelle.

</Callout>

### Erreur de validation [#validation-error]

Quand `error` est fourni :

- Les styles d'erreur sont appliqués
- `aria-invalid` est fixé
- Le texte de l'erreur est connecté au champ via `aria-describedby` et `aria-errormessage`
- Le texte de l'erreur a `role="alert"`, il est donc annoncé immédiatement lorsqu'il apparaît - y compris lorsque le champ est déjà concentré, pas seulement sur le prochain événement focus
- un consommateur fourni `aria-describedby` est composé avec les propres helper/error ids du champ plutôt que remplacé, donc les deux descriptions restent disponibles pour la technologie d'assistance

### Tailles disponibles [#available-sizes]

| Taille | Objet                                                                       |
| ------ | --------------------------------------------------------------------------- |
| `sm`   | Interfaces utilisateur denses, tableaux, filtres, barres d'outils compactes |
| `md`   | Taille de saisie par défaut                                                 |
| `lg`   | Onboarding, auth, formes marketing, flux proéminents                        |

<Callout type="info" title="Règle de densité">
  Utilisation `md` par défaut. Utilisation `sm` pour les surfaces de produits
  denses et `lg` lorsque la forme a besoin d'une plus grande importance.

</Callout>

## Entrée vs Mot de passeInput vs Textarea [#input-vs-passwordinput-vs-textarea]

| Situation                                | Utilisation                                 |
| ---------------------------------------- | ------------------------------------------- |
| Valeur de texte court                    | Entrées                                     |
| Email, nom, slug, URL                    | Entrées                                     |
| Mot de passe avec révélation             | PasswordInput                               |
| Contenu long et libre                    | Textarea ou champ personnalisé              |
| Champ de recherche                       | Entrée avec icône principale                |
| Entrée numérique ou monétaire            | Entrée avec formatage spécifique au domaine |
| Choisissez-en un parmi les options fixes | Sélectionnez, RadioGroup ou Tabs selon UX   |

<Callout title="Règle de décision">
  Utilisez Input pour le texte court. Utilisez PasswordInput pour les secrets.
  Utilisez un champ plus grand pour le contenu long.

</Callout>

## API [#api]

#### Props [#props]

| Prop         | Type                   | Par défaut | Désignation                             |
| ------------ | ---------------------- | ---------- | --------------------------------------- |
| `label`      | `string`               | —          | Étiquette accessible au-dessus du champ |
| `helperText` | `string`               | —          | Texte d'aide sous le champ              |
| `error`      | `string`               | —          | Message d'erreur de validation          |
| `leftIcon`   | `React.ReactNode`      | —          | Icône affichée à gauche                 |
| `rightIcon`  | `React.ReactNode`      | —          | Icône affichée à droite                 |
| `size`       | `"sm" \| "md" \| "lg"` | `"md"`     | Densité visuelle                        |
| `className`  | `string`               | —          | Dépassement du vent arrière             |

L'entrée étend les props d'entrée standard, à l'exclusion de la `size` attribut.

```ts title="input-props.ts"
React.InputHTMLAttributes<HTMLInputElement>;
```

### TypeScript types [#typescript-types]

```ts title="input-types.ts"
export type InputSize = "sm" | "md" | "lg";

export interface InputProps extends Omit<
  React.InputHTMLAttributes<HTMLInputElement>,
  "size"
> {
  label?: string;
  helperText?: string;
  error?: string;
  leftIcon?: React.ReactNode;
  rightIcon?: React.ReactNode;
  size?: InputSize;
}
```

### Accessibilité [#accessibility]

L'entrée est conçue pour prendre en charge la composition de formulaire accessible.

Directives :

- Utiliser un visible `label` quand le terrain a besoin de contexte
- Ne vous fiez pas au texte d'espace réservé comme seule étiquette
- `error` devrait fixer `aria-invalid`
- helper et le texte d'erreur doivent être connectés via `aria-describedby`
- texte d'erreur est également annoncé en direct via `role="alert"` Le moment où il apparaît
- `disabled` réduit le champ et affiche un curseur non autorisé sur le champ lui-même, pas seulement sur l'attribut natif - l'état visuel et l'état fonctionnel correspondent toujours
- icônes décoratives devraient utiliser `aria-hidden="true"`
- Gardez les anneaux de focus visibles
- Utiliser un natif approprié `type` valeurs, telles que `email`, `url`, `tel`ou `search`
- utilisation `autoComplete` valeurs, le cas échéant

<Callout title="Règle d'accessibilité">
  Chaque entrée a besoin d'un nom accessible. Une étiquette visible est
  généralement le choix le plus sûr.

</Callout>

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="L'entrée doit-elle valider les valeurs elle-même ?">
    Non. L'entrée affiche l'état de validation. Votre formulaire, schéma, serveur ou couche de domaine doit définir ce qui est valide.
  </Accordion>

<Accordion title="Un texte réservé peut-il remplacer une étiquette ?">
  Non. Le texte de l'espace réservé disparaît lors de la saisie et ne suffit pas
  pour la structure de formulaire accessible.
</Accordion>

<Accordion title="Quand dois-je utiliser le texte d'aide?">
  Utilisez le texte d'aide lorsqu'il réduit l'incertitude, explique la mise en
  forme ou clarifie la façon dont la valeur sera utilisée.
</Accordion>

  <Accordion title="Les icônes peuvent-elles être interactives ?">
    Si une icône déclenche une action, il devrait s'agir d'un bouton réel avec une étiquette accessible. Pour la visibilité du mot de passe, utilisez PasswordInput.
  </Accordion>
</Accordions>
