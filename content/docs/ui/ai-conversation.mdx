## Compose your conversation

`AIConversation` displays a scrollable, labelled message list. It follows new content
while the reader is at the end and preserves their position when they scroll back.
Your application supplies messages and transport; this component makes no model requests.

<Callout title="Package availability">
  AIConversation, AIMessage and AIMessageActions are introduced by the
  conversation primitives minor Changeset. Use the repository workspace until
  that release is published. They are not exported by `@pycolors/ui@1.6.1` or
  earlier.
</Callout>

## Controlled composition

```tsx title="conversation.tsx"
"use client";

import { AIConversation, AIMessage, AIMessageActions } from "@pycolors/ui";

type Message = { id: string; author: string; text: string };

export function Conversation({ messages }: { messages: Message[] }) {
  return (
    <AIConversation
      label="Support conversation"
      messagesLabel="Support messages"
    >
      {messages.map((message) => (
        <AIMessage
          key={message.id}
          author={message.author}
          actions={
            <AIMessageActions
              value={message.text}
              copyAriaLabel={`Copy ${message.author} message`}
              onCopy={(text) => navigator.clipboard.writeText(text)}
            />
          }
        >
          {message.text}
        </AIMessage>
      ))}
    </AIConversation>
  );
}
```

Place [AIComposer](/docs/ui/ai-composer) after the conversation. Keep request errors,
retry and cancellation in your consumer, or use the [AI Chat Block](/docs/blocks/app-shells/ai-chat)
for the complete composed surface. This component does not parse Markdown or HTML.

## Behavior and accessibility

<Steps>

<Step>

### Supply semantic messages

Children belong to an ordered list. Render `AIMessage` or native `li` elements,
with stable keys. The empty state belongs outside that list. Use a meaningful
`label` and `messagesLabel` when more than one conversation appears on the page.

</Step>

<Step>

### Respect reading position

The focusable viewport follows content and resize changes while at the end.
Scrolling more than 32 pixels away pauses following. Returning near the end or
choosing **Jump to latest** resumes it. Layout changes do not force a reader back
to the bottom. Without ResizeObserver, React child updates still follow.

</Step>

<Step>

### Announce request state in your application

The message list is not a live region: streaming tokens must not repeatedly
interrupt a screen reader. Provide concise request-status announcements outside
the list. Jumping uses immediate scrolling and restores viewport focus without
animated motion. Keyboard and screen-reader verification remain part of your
application's integration checks.

</Step>

</Steps>

## API

| Prop                          | Default          | Purpose                                               |
| ----------------------------- | ---------------- | ----------------------------------------------------- |
| `children`                    | —                | Semantic list items, usually AIMessage instances      |
| `label`                       | `Conversation`   | Accessible viewport name                              |
| `messagesLabel`               | `Messages`       | Accessible ordered-list name                          |
| `jumpLabel`                   | `Jump to latest` | Visible return button label                           |
| `viewportClassName`           | —                | Override the default `max-h-[28rem]` viewport styling |
| `className`, native div props | —                | Outer wrapper attributes and styling                  |
| `ref`                         | —                | Outer HTMLDivElement, not the inner viewport          |

Slots: `ai-conversation` and `ai-conversation-viewport`. Caller classes use the
standard PyColors `cn()` precedence. The viewport owns its scroll handling and
focus behavior. Use a stable component key to reset an entire conversation.
