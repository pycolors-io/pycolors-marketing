## Flux de travail latéraux sans quitter le contexte [#side-workflows-without-leaving-context]

Les **Sheet** component est un panneau coulissant utilisé pour les workflows latéraux, les filtres, la navigation et l'édition contextuelle.

Utilisez-le pour:

- Filtres avancés
- navigation mobile
- panneaux d'édition latéraux
- panneaux de détail
- paramètres contextuels
- flux de travail secondaires qui devraient préserver le contexte de la page

La feuille est construite sur **Boîte de dialogue Radix** et stylisé avec des tokens sémantiques PyColors tels que `bg-card`, `border-border`et `text-foreground`.

<Callout title="Idée de base">
  Sheet maintient l'utilisateur dans son contexte tout en exposant un flux de
  travail secondaire plus important.

</Callout>

### Orientation en matière de placement [#placement-guidance]

| Côté     | Idéal pour                                               |
| -------- | -------------------------------------------------------- |
| `right`  | Montage, détails, panneaux contextuels                   |
| `left`   | Navigation, menu de l'application, barre latérale mobile |
| `top`    | Filtres globaux, annonces, commandes compactes           |
| `bottom` | Action mobile-first, contrôles rapides                   |

<Callout title="Règle de placement">
  Utilisation `right` pour l'édition, `left` pour la navigation, et `bottom`
  pour les panneaux d'action mobiles.

</Callout>

### Utilisations [#usage-patterns]

<Steps>
  <Step>
    #### Choisissez le bon côté [#choose-the-right-side]

    Choisissez le placement en fonction du flux de travail : à droite pour les détails, à gauche pour la navigation, en bas pour les actions mobiles.

</Step>

  <Step>
    #### Gardez le contexte de la page visible [#keep-the-page-context-visible]

    Une feuille devrait prolonger la page, pas la remplacer. Évitez de l'utiliser pour les flux qui ont besoin d'une page complète.

</Step>

  <Step>
    #### Fournir le titre et la description [#provide-title-and-description]

    Utilisation `SheetTitle` et `SheetDescription` afin que les utilisateurs comprennent le but du panel.

</Step>

  <Step>
    #### Utilisez une action principale [#use-one-primary-action]

    La plupart des feuilles devraient avoir une action principale et une action secondaire de fermeture ou d'annulation.

</Step>

  <Step>
    #### Manipuler le défilement intentionnellement [#handle-scroll-intentionally]

    Évitez les conteneurs de défilement imbriqués. Préférez une région à défilement clair à l'intérieur de le panneau latéral.

</Step>

</Steps>

## Menu Sheet vs Dialog vs Dropdown [#sheet-vs-dialog-vs-dropdown-menu]

| Situation                                   | Utilisation    |
| ------------------------------------------- | -------------- |
| Filtres avancés                             | Sheet          |
| Panneau d'édition latéral                   | Sheet          |
| Navigation mobile                           | Sheet          |
| Enregistrer les détails du panneau          | Sheet          |
| Courte confirmation destructive             | boîte dialogue |
| Petite liste d'actions contextuelles        | menu déroulant |
| Flux de travail complet en plusieurs étapes | Page           |

<Callout type="info" title="Règle de décision">
  Sheet est pour les flux de travail latéraux. Le dialogue est pour des
  décisions ciblées. Le menu déroulant est pour les choix compacts.

</Callout>

## API [#api]

#### Composante [#component]

| Composante         | Désignation                                               |
| ------------------ | --------------------------------------------------------- |
| `Sheet`            | Récipient racine                                          |
| `SheetTrigger`     | Élément déclencheur, généralement avec `asChild`          |
| `SheetClose`       | Fermez le contrôle, généralement en enveloppant un bouton |
| `SheetContent`     | Surface du panneau coulissant                             |
| `SheetHeader`      | Titre et description stack helper                         |
| `SheetFooter`      | Action Row Helper                                         |
| `SheetTitle`       | Titre de feuille accessible                               |
| `SheetDescription` | Texte d ' appui                                           |

#### SheetContent props [#sheetcontent-props]

| Prop        | Type                            | Par défaut | Désignation                |
| ----------- | ------------------------------- | ---------- | -------------------------- |
| `side`      | `SheetSide`                     | `"right"`  | Placement du panel         |
| `className` | `string`                        | —          | Autres classes Tailwind    |
| `...props`  | `DialogPrimitive.Content` props | —          | Radix Dialog Contenu props |

`Sheet`, `SheetTrigger`et `SheetClose` sont des réexportations de primitives Radix Dialog et acceptent leurs props natifs.

### TypeScript types [#typescript-types]

```ts title="sheet-types.ts"
export type SheetSide = "top" | "bottom" | "left" | "right";

export interface SheetContentProps extends React.ComponentPropsWithoutRef<
  typeof DialogPrimitive.Content
> {
  side?: SheetSide;
}
```

### Accessibilité [#accessibility]

Sheet est construit sur les primitives Radix Dialog.

Cela signifie :

- La focus est piégée alors qu’elle est ouverte
- se concentrer revient au déclencheur à la fermeture
- Escape ferme le panneau latéral par défaut
- les lecteurs d'écran reçoivent la sémantique de dialogue
- `SheetTitle` Fournir le nom accessible

Directives :

- utilisation `SheetTrigger asChild` avec un déclencheur sémantique
- Inclure une claire `SheetTitle`
- Inclure un utile `SheetDescription`
- éviter d'utiliser Sheet pour les confirmations destructives
- éviter les feuilles imbriquées
- éviter les longs flux en plusieurs étapes à l'intérieur d'un panneau latéral

<Callout title="Règle d'accessibilité">
  Une feuille se comporte toujours comme un dialogue. Il a besoin d'un
  étiquetage clair, d'une gestion ciblée et d'une tâche limitée.

</Callout>

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Sheet est-il différent de Dialog ?">
    Sheet est implémenté avec les primitives Dialog, mais le modèle d'interaction est différent. La boîte de dialogue est pour les décisions modales ciblées. Sheet est destiné aux workflows latéraux qui préservent le contexte de la page.
  </Accordion>

<Accordion title="Les filtres doivent-ils utiliser le panneau latéral ou le menu déroulant?">
  Utilisez le menu déroulant pour quelques options compactes. Utilisez Sheet
  lorsque les filtres sont nombreux, groupés ou ont besoin de plus
  d'explications.
</Accordion>

<Accordion title="Une feuille peut-elle contenir un formulaire ?">
  Oui. Les feuilles fonctionnent bien pour l'édition contextuelle et les
  formulaires de filtre. Pour les formulaires longs ou à plusieurs étapes,
  utilisez une page dédiée.
</Accordion>

  <Accordion title="Les actions destructrices devraient-elles utiliser Sheet?">
    Habituellement non. Utilisez la boîte de dialogue pour les confirmations destructrices, car la décision doit être ciblée et explicite.
  </Accordion>
</Accordions>
