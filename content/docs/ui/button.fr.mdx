## Actions auxquelles les utilisateurs peuvent faire confiance [#actions-users-can-trust]

Les **Bouton** component est la primitive d'action primaire dans PyColors UI.

Utilisez-le pour:

- Soumettre des formulaires
- Déclenchement des dialogues
- ouverture feuilles
- Débuter le paiement
- enregistrer les changements
- Confirmer les actions destructrices
- naviguer quand un élément doit se comporter visuellement comme un bouton

Cette mise en œuvre étend la **primitive de bouton shadcn/ui** et est aligné avec le système de conception PyColors: tokens de couleur sémantiques, rayon, ombres et anneaux de focus.

<Callout title="Idée de base">
  Les boutons communiquent l'intention. Choisissez la variante en fonction de la
  priorité d'action et non de la décoration.

</Callout>

## Modèle d'action produit [#product-action-model]

Les boutons sont l'une des primitives d'interaction à la plus haute fréquence dans un produit SaaS.

Ils influencent :

- clarté de conversion
- Confiance dans le workflow
- action destructrice sécurité
- friction d'embarquement
- Qualité perçue des produits

<Callout title="Modèle mental">
  Un bouton n’est pas une décoration. C’est un engagement d’interaction.

</Callout>

### Variantes disponibles [#available-variants]

| Variante      | Objet                                                            |
| ------------- | ---------------------------------------------------------------- |
| `default`     | Action principale, priorité absolue                              |
| `secondary`   | Action alternative neutre                                        |
| `outline`     | Action à moyen terme                                             |
| `ghost`       | Action de faible accentuation dans l'interface utilisateur dense |
| `destructive` | Action dangereuse ou irréversible                                |
| `link`        | Action en ligne de style texte                                   |

<Callout type="info" title="Variante de règle">
  Une page doit généralement avoir une action primaire claire. Utilisez
  secondaire, contour ou fantôme pour soutenir les actions.

</Callout>

Ceci est couramment utilisé pour les liens et les composants de routeur.

## Bouton vs lien vs badge [#button-vs-link-vs-badge]

| Situation                                          | Utilisation                          |
| -------------------------------------------------- | ------------------------------------ |
| Soumettre un formulaire                            | Bouton                               |
| Déclencher une mutation                            | Bouton                               |
| Ouvrir une boîte de dialogue ou un panneau latéral | Bouton                               |
| Naviguer vers une autre URL                        | Lien stylé avec `Button asChild`     |
| Afficher les métadonnées ou l'état                 | Badge                                |
| Navigation texte en ligne                          | Lien                                 |
| Actions de rangée compactes                        | Bouton de déclenchement DropdownMenu |

<Callout title="Règle de décision">
  Le bouton est pour l'intention. Link est pour la navigation. Badge pour les
  métadonnées.

</Callout>

## API [#api]

| Prop        | Type            | Par défaut  | Désignation              |
| ----------- | --------------- | ----------- | ------------------------ |
| `variant`   | `ButtonVariant` | `"default"` | Style visuel             |
| `size`      | `ButtonSize`    | `"default"` | Taille du bouton         |
| `asChild`   | `boolean`       | `false`     | Rendu avec Radix Slot    |
| `disabled`  | `boolean`       | `false`     | Désactiver l'interaction |
| `className` | `string`        | —           | Autres classes Tailwind  |

### Accessibilité [#accessibility]

- Utilisez des étiquettes claires et descriptives.
- Préserver les styles de focus clavier.
- Utilisez des boutons d'icône uniquement avec un `aria-label`.
- Marquer les icônes décoratives avec `aria-hidden="true"`.
- Utilisation `disabled` pour des actions indisponibles.
- Ne comptez pas uniquement sur la couleur pour communiquer un état destructeur ou invalide.
- Utilisez des liens pour la navigation et des boutons pour les actions.

<Callout title="Règle d'accessibilité">
  Chaque bouton doit avoir un nom accessible. Le texte visible est le meilleur;
  `aria-label` est nécessaire pour les boutons icon-only.

</Callout>

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Faut-il utiliser le bouton de navigation ?">
    La navigation doit utiliser des liens. Utilisation `Button asChild` pour styliser un lien d'ancrage ou de routeur comme un bouton.
  </Accordion>

<Accordion title="Combien de boutons principaux une page doit-elle avoir ?">
  Généralement une par grande section. Trop de boutons primaires affaiblissent
  la hiérarchie.
</Accordion>

<Accordion title="Quand devrais-je utiliser destructif?">
  Utilisation `destructive` pour des actions dangereuses ou irréversibles,
  telles que la suppression, la révocation, la suppression ou l'annulation de
  l'abonnement.
</Accordion>

  <Accordion title="Les boutons désactivés devraient-ils expliquer pourquoi ils sont désactivés?">
    Oui. Utilisez le texte d'aide à proximité, les messages de validation ou la copie d'état pour expliquer ce qui est requis.
  </Accordion>
</Accordions>
