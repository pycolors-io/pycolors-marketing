## Pourquoi le versioning est important [#why-versioning-matters]

PyColors utilise le Versioning sémantique pour rendre les mises à jour prévisibles, sûres et faciles à comprendre.

Un numéro de version doit communiquer immédiatement :

- Le niveau de changement
- risque de mise à niveau
- Compatibilité Attentes
- les besoins migratoires

Cette politique vise à réduire l’incertitude dans l’ensemble de l’écosystème.

<Callout title="Principe de base">
  Les développeurs devraient être en mesure de comprendre l'impact de la mise à
  niveau avant de lire le journal des modifications.

</Callout>

## Référence du versioning sémantique [#semantic-versioning-baseline]

Les packages PyColors, les starters, les templates et les outils partagés suivent Semantic Versioning.

```txt title="semver.txt"
MAJOR.MINOR.PATCH
```

## Interprétation pratique [#practical-interpretation]

En pratique, le type de version répond à une question :

> L'utilisateur peut-il effectuer une mise à niveau en toute sécurité sans migration ?

| Situation                                       | Type de publication |
| ----------------------------------------------- | ------------------- |
| Réparer les bugs ou polir                       | Patch               |
| Ajout de fonctionnalités rétrocompatibles       | Mineur              |
| Exiger la migration ou changer la compatibilité | Majeur              |

<Callout type="info" title="Importante distinction">
  Une grande quantité de travail ne signifie pas automatiquement une publication
  majeure. Le facteur déterminant est l'impact de la compatibilité.

</Callout>

## Ce qui n’est pas une publication majeure [#what-is-not-a-major-release]

Les modifications suivantes restent généralement des versions patch ou mineures :

- Visuel polonais
- documentation restructuration
- Refactors internes
- amélioration des performances
- nouvelles API optionnelles
- nouvelles sections de démarrage
- Améliorations du système de conception additive

Une version ne devient majeure que lorsque les attentes en matière de compatibilité changent.

## Objectifs de version [#versioning-goals]

Cette politique est conçue pour fournir :

- Mises à jour prévisibles
- attentes de compatibilité transparentes
- Consommation de colis stable
- frontières migratoires claires
- adoption à long terme plus sûre
- Confiance plus forte des développeurs

<Callout title="Principe de confiance">
  Le versioning stable fait partie de l’expérience produit, pas seulement un
  détail technique.

</Callout>

### Relation avec les rejets de l'écosystème [#relationship-with-ecosystem-releases]

Versioning sémantique s'applique aux versions de paquets techniques.

L'écosystème plus large de PyColors communique les progrès séparément par :

- Libérations hebdomadaires
- changelog mises à jour
- Progression de le panneau latéral de route
- annonces d'écosystèmes

Cette séparation permet de garder la vérité technique précise tout en facilitant la progression du produit.
