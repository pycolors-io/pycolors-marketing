## Vue d’ensemble [#overview]

Starter Free est conçu pour vous faire passer de zéro à une surface SaaS utilisable en quelques minutes.

À la fin de ce guide, vous aurez un environnement produit local fonctionnant avec:

- auth écrans
- tableau de bord
- projets
- admin
- facturation
- paramètres

Pas de base de données. Pas de touches Stripe. Pas de secrets.

Starter Free est intentionnellement simulé afin que vous puissiez évaluer la surface du produit avant de câbler les services backend.

<Callout title="Qu'est-ce que Starter Free">
  Starter Free vous aide à valider rapidement l'orientation du produit avec une
  surface d'interface utilisateur adaptées à la production, sans avoir besoin
  d'auth, de facturation ou de configuration de la base de données.

</Callout>

## Préalables [#prerequisites]

Assurez-vous que votre environnement comprend :

- Node.js 18 ou plus récent
- pnpm
- Git

Recommandé : utilisez la dernière version de Node.js LTS.

<Tabs items={["Vérifier les versions", "Installer pnpm"]}>
  <Tab value="Vérifier les versions">

```bash title="terminal"
node -v
pnpm -v
git --version
```

</Tab>

  <Tab value="Installer pnpm">

```bash title="terminal"
npm install -g pnpm
```

</Tab>

</Tabs>

<Callout type="info" title="Gestionnaire de paquets">
  Starter Free est conçu autour de pnpm. L'utilisation de npm ou de laine peut
  créer des incohérences de fichier de verrouillage et de dépendance.

</Callout>

## Étapes [#steps]

<Steps>

<Step>
### Cloner le dépôt [#clone-the-repository]

Clonez le starter et allez dans le répertoire du projet.

```bash title="terminal"
git clone https://github.com/pycolors-io/pycolors-starter-free.git
cd pycolors-starter-free
```

</Step>

<Step>
### Installer les dépendances [#install-dependencies]

Installez la base de référence locale.

```bash title="terminal"
pnpm install
```

Ceci installe la pile de démarrage :

| Zone de dépendance | Inclus             |
| ------------------ | ------------------ |
| Cadre              | Next.js App Router |
| Styling            | Tailwind CSS v4    |
| UI                 | PyColors UI        |
| Langue             | TypeScript         |
| Qualité            | ESLint             |

</Step>

<Step>
### Démarrez le serveur de développement [#start-the-development-server]

Exécutez l'application localement.

```bash title="terminal"
pnpm dev
```

Puis ouvrir :

```txt title="browser"
http://localhost:3000
```

Vous devriez atterrir sur la surface locale du produit Starter Free.

</Step>

<Step>
### Valider le starter [#validate-the-starter]

Ouvrez les routes principales :

```txt title="routes"
/
/login
/register
/dashboard
/projects
/admin
/billing
/settings
```

Si les routes se chargent correctement et que la navigation fonctionne, l'installation est terminée.

<Callout type="info" title="Comportement attendu">
  Starter Free est intentionnellement simulé. Vous devriez être en mesure d'explorer les écrans, les mises en page et les flux de produits immédiatement sans configuration backend ou configuration secrète.

</Callout>

</Step>

</Steps>

## Les premières choses à essayer [#first-things-to-try]

Une fois que l'application est en cours d'exécution, faites un petit changement de produit avant de brancher quoi que ce soit.

<Tabs items={["Tableau de bord", "Entité", "Données fictives"]}>
  <Tab value="Tableau de bord">

Modifiez le titre du tableau de bord.

```txt title="file"
app/(app)/dashboard/page.tsx
```

Modifiez le texte d'en-tête et enregistrez. Le rechargement à chaud devrait mettre à jour le navigateur instantanément.

</Tab>

  <Tab value="Entité">

Renommer l'entité principale.

```txt title="search"
Projects
```

Le starter est intentionnellement facile à adapter à votre propre modèle de domaine.

</Tab>

  <Tab value="Données fictives">

Mettre à jour les données du produit simulé.

```txt title="file"
components/projects/project-types.ts
```

Modifiez les projets fictifs pour mieux correspondre à la direction de votre produit.

</Tab>

</Tabs>

## Pièges courants [#common-pitfalls]

Starter Free ne nécessite pas :

- URL de la base de données
- Auth Secrets
- Touches à rayures
- informations d'identification du fournisseur de messagerie
- Configuration de l'API backend

Tout est ridiculisé par le design.

## Dépannage [#troubleshooting]

<Accordions type="single">
  <Accordion title="Port déjà utilisé">
    Exécutez le serveur de développement sur un autre port.

```bash title="terminal"
pnpm dev --port 3001
```

  </Accordion>

  <Accordion title="Erreurs de version du nœud">
    Vérifiez votre version de Node.js.

```bash title="terminal"
node -v
```

    Mettre à niveau vers une version LTS actuelle de Node.js, puis réinstaller les dépendances.

  </Accordion>

  <Accordion title="Utilisation de npm ou de fil par erreur">
    Supprimez npm lockfiles et réinstallez-le avec pnpm.

```bash title="terminal"
rm -rf node_modules package-lock.json yarn.lock
pnpm install
```

  </Accordion>

  <Accordion title="Créer des problèmes après avoir tiré les mises à jour">
    Effacer l'état local généré et réinstaller les dépendances.

```bash title="terminal"
rm -rf node_modules .next
pnpm install
pnpm dev
```

  </Accordion>
</Accordions>
