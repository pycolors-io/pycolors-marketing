## Déploiement prêt pour la production [#production-ready-deployment]

Starter Pro est conçu pour passer du développement local à la production sans reconstruire la couche d'infrastructure.

Le modèle de déploiement se concentre sur :

- Infrastructure prévisible
- gestion de l'environnement sécurisé
- livraison SaaS évolutive
- Fiabilité de la facturation Stripe
- Flux d'authentification protégés
- Valeurs par défaut

<Callout title="Principe de base">
  Le déploiement devrait accélérer la confiance de lancement, pas devenir un
  autre projet d'ingénierie.

</Callout>

## Flux de déploiement recommandé [#recommended-deployment-flow]

<Steps>
  <Step>
    ### Configurer l'infrastructure [#configure-infrastructure]

    Provisionnez PostgreSQL, configurez des domaines de production et préparez des variables d'environnement.

</Step>

  <Step>
    ### Configurer l'authentification [#configure-authentication]

    Définissez les secrets d'authentification de production, les fournisseurs OAuth et la configuration de l'hôte de confiance.

</Step>

  <Step>
    ### Configurer Stripe [#configure-stripe]

    Créez des produits, des prix, des webhooks et une configuration de facturation de production.

</Step>

  <Step>
    ### Déployer l'application [#deploy-the-application]

    Poussez l'application vers la production et validez la configuration de l'environnement.

</Step>

  <Step>
    ### Valider les flux de production [#validate-production-flows]

    Authentification de test, synchronisation de facturation, protection des routes, paiement et accès aux abonnements.

</Step>

</Steps>

## Liste de contrôle de production Stripe [#stripe-production-checklist]

Avant d’accepter des paiements réels :

- Configurer les clés Stripe Live
- créer des produits de production et des prix
- Configurer les webhooks de production
- valider la livraison du webhook
- débit de contrôle
- test Facturation Portail flux
- valider la synchronisation de l'abonnement
- confirmer les règles d'accès à la facturation

```bash title="stripe-webhooks.sh"
stripe listen --forward-to localhost:3000/api/webhooks/stripe
```

## Déploiement de bases de données [#database-deployment]

Starter Pro utilise Prisma avec PostgreSQL.

Installation de production typique:

```bash title="database-setup.sh"
pnpm db:migrate
pnpm db:generate
```

Pratiques recommandées:

- Hébergement PostgreSQL géré
- sauvegardes automatisées
- connexion pooling
- bases de données de production et d'échelonnement distinctes
- workflow de migration en toute sécurité

### Philosophie de déploiement [#deployment-philosophy]

Starter Pro se sépare intentionnellement :

- infrastructure
- logique du produit
- logique de facturation
- limites auth
- Surfaces d'interface utilisateur

Cela vous permet de :

- Déploiement plus rapide
- Fonctionnalités d'échelle en toute sécurité
- Gardez la facturation fiable
- réduire les erreurs de production
- maintenir la vitesse du produit à long terme

<Callout title="Pourquoi cela compte">
  La plupart des lancements SaaS ralentissent parce que l’infrastructure et la
  logique des produits sont étroitement liées. Starter Pro maintient ces
  préoccupations séparées dès le début.

</Callout>

## Ce que vous devez personnaliser [#what-you-should-customize]

Vous personnalisez généralement :

- branding
- copie du produit
- stratégie de prix
- workflows produits
- Surfaces de tableau de bord
- entités de domaine

Habituellement, vous conservez :

- structure de déploiement
- auth fondations
- infrastructure de facturation
- Routage protégé
- Synchronisation Stripe
- modèle d'environnement
- Limites du serveur
