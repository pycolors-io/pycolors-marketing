## Ce que cela résout [#what-this-solves]

L'authentification est généralement l'un des premiers bloqueurs sérieux avant le lancement.

Il semble simple au niveau de l'interface utilisateur:

- connexion
- enregistrer
- mot de passe oublié
- Boutons OAuth

Mais la production auth a également besoin:

- mot de passe hashing
- session persistance
- e-mail vérification
- mot de passe reset tokens
- compte fournisseur reliant
- comportement de la route protégée
- Règles de déconnexion sécurisées
- Taux limitant les fondations
- Gestion des erreurs sécurisées

Starter Pro vous donne une base structurée pour cette couche afin que vous ne reconstruisiez pas le cycle de vie complet à partir de zéro.

## Architecture [#architecture]

### Responsabilités du modèle de données [#data-model-responsibilities]

Starter Pro auth est conçu autour des structures dont un SaaS sérieux a généralement besoin.

Les responsabilités typiques de l'auth comprennent:

| Zone              | Objet                                                                     |
| ----------------- | ------------------------------------------------------------------------- |
| Utilisateur       | Identité, email, image de profil, état de vérification                    |
| Compte            | Comptes fournisseurs OAuth et liens de compte                             |
| Session           | Sessions utilisateur actives                                              |
| VerificationToken | Flux de vérification compatibles avec Auth.js                             |
| UserToken         | Cycle de vie de la vérification et de la réinitialisation du mot de passe |
| AuthAttempt       | Audit et base de limitation de taux                                       |

<Callout type="info" title="Pourquoi cela compte">
  Production auth ne consiste pas seulement à se connecter. Il s'agit de stocker
  suffisamment d'état pour sécuriser le cycle de vie du compte, la récupération
  et la logique du fournisseur.

</Callout>

### Routes protégées [#protected-routes]

L'Auth devient précieux lorsqu'il protège les surfaces réelles des produits.

Starter Pro est conçu pour que la couche auth puisse protéger :

- tableau de bord
- paramètres
- facturation
- admin
- données client
- zones de produits plan-conscient

```txt title="protected-routes.txt"
/dashboard
/settings
/billing
/admin
```

Un bon système de routes protégées devrait :

- rediriger les utilisateurs anonymes
- Préserver les limites sécurisées des applications
- exposer l'interface utilisateur consciente de la session
- éviter les fuites d'état privé
- travailler avec les règles de facturation et de propriété backend

### Intégration avec la facturation [#integration-with-billing]

Auth et la facturation sont connectés dans un SaaS réel.

Un client n’est pas seulement un enregistrement de paiement. Un client appartient à un utilisateur ou à une organisation.

Cela signifie qu'auth doit prendre en charge :

- identité du compte
- propriété du client
- accès abonnement
- accès au portail de facturation
- Fonctionnalités adapté à l’offre

<Callout title="Pourquoi Auth est important pour les revenus">
  Vous ne pouvez pas facturer les clients de manière fiable tant que vous ne
  pouvez pas les identifier de manière fiable.

</Callout>

Avant de traiter l'auth comme prêt au lancement, validez :

- identifiants de connexion
- OAuth se connecter

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Est-ce que c'est juste UI autour de Auth?">
    Non. Starter Pro se concentre sur le comportement réel de l'authentification : sessions, fournisseurs, tokens, routes protégées et structure du cycle de vie du compte.
  </Accordion>

<Accordion title="Puis-je supprimer un fournisseur ?">
  Oui. Les fournisseurs doivent être traités comme des points d'entrée
  configurables. Gardez les règles de secours de compte sécurisé si vous
  autorisez les utilisateurs à déconnecter les fournisseurs.
</Accordion>

<Accordion title="La facturation doit-elle dépendre d’auth ?">
  Oui. Dans un SaaS, l’état de facturation doit être connecté à une identité
  d’utilisateur, de client ou d’organisation. Auth est le fondement de cette
  propriété.
</Accordion>

  <Accordion title="Puis-je remplacer le fournisseur d'authentification plus tard?">
    Vous pouvez, mais Auth touche de nombreuses parties d'un produit. Remplacez-le délibérément et gardez les mêmes limites autour des sessions, des tokens et des accès protégés.
  </Accordion>
</Accordions>
