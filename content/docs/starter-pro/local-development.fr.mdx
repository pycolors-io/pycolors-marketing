## L’environnement local doit être réel [#local-environments-should-feel-real]

Starter Pro est conçu de manière à ce que le développement local valide un comportement SaaS réaliste au lieu de pages de démonstration déconnectées.

L’environnement local soutient :

- Authentification
- facturation
- Routes protégées
- Prisma
- Stripe
- Comportement PWA
- workflows adaptées à la production

## Pourquoi cela compte [#why-this-matters]

De nombreux produits SaaS deviennent difficiles à mettre à l’échelle car les environnements de développement locaux ne reflètent jamais le comportement réel de la production.

Cela crée généralement :

- Flux d'auth incohérents
- Facturation
- Onboarding cassé
- Hypothèses de déploiement dangereuses
- régressions UX mobiles
- Configuration de l'environnement fragile

Starter Pro est structuré pour réduire cette dérive opérationnelle dès le début.

```txt title="local-development-model.txt"
Local setup
  ↓
Environment variables
  ↓
Database
  ↓
Auth
  ↓
Billing
  ↓
Protected routes
  ↓
PWA behavior
  ↓
Production confidence
```

<Callout type="info" title="Aperçu de la production">
  Une configuration locale forte n'est pas seulement une question de commodité.
  C'est la première porte de sortie pour votre infrastructure de produits.

</Callout>

## Débit de configuration recommandé [#recommended-setup-flow]

<Steps>
  <Step>
    ### Installer les dépendances [#install-dependencies]

```bash
pnpm install
```

</Step>

  <Step>
    ### Configurer les variables d'environnement [#configure-environment-variables]

```bash
cp .env.example .env.local
```

</Step>

  <Step>
    ### Démarrage de l'infrastructure [#start-infrastructure]

```bash
pnpm db:up
```

</Step>

  <Step>
    ### Semer et migrer [#seed-and-migrate]

```bash
pnpm app:setup
```

</Step>

  <Step>
    ### Lancer le développement [#start-development]

```bash
pnpm dev
```

</Step>

</Steps>

## Liste de contrôle de validation recommandée [#recommended-validation-checklist]

Valider :

- Flux d'authentification
- routes de facturation
- Pages protégées
- réactivité mobile
- Installabilité PWA
- comportement de secours hors ligne
- Réglages des surfaces
- les données d’exemple locales

<Callout type="info" title="Principe de validation">
  Validez les flux de produits réels localement avant de les personnaliser en
  profondeur.

</Callout>

<Callout type="info" title="Un aperçu du plan, pas un test de paiement">
  Free to Pro s'exécute localement dans le navigateur et se réinitialise en
  quittant la facturation ou le rechargement. Il ne crée aucun abonnement ou
  droit payé et ne modifie aucune permission de démonstration ou quota. La

  webhook restent bloqués sur le serveur. Vérifiez la validation Stripe et les

Les inclus `DEMO.md` documents dédiés à la configuration de la base de données, aux invitations simulées, à l'expiration des visiteurs et au nettoyage. Les liens publics dépendent d'un déploiement de démonstration vérifié; ils ne sont pas activés par ces seules instructions locales.

Les [recette d'entreprise pas à pas](/docs/starter-pro/recipes) vous donner des scénarios concrets de projet, de tâche et de commentaire à essayer avec des données fictives. Conservez l'accès à leur espace de travail, archivez et rechargez les contrôles lors de l'adaptation de l'interface.
