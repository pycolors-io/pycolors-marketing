<Callout title="Quotas et propriété de la facturation">
  Les quotas par défaut `null`, signifiant **non plafonné**. Utilisez des
  entiers non négatifs lorsque votre offre a besoin de limites, puis testez la
  limite et le chemin de mise à niveau. La facturation reste personnelle; un
  abonnement appartenant à une organisation nécessite une conception distincte.

</Callout>

Personnaliser fournit la palette, la typographie, la géométrie, l'échelle d'interface et les contrôles de barre latérale dans le navigateur. La langue et le fuseau horaire sont des préférences de compte. Examiner les changements dans les deux thèmes, français / anglais, mises en page étroites et mouvement réduit. Les expédiés `docs/customization.md` explique le logo, l'icône et les points d'entrée e-mail.

## Configurer l'apparence [#configure-appearance]

Utilisez le [Theme Builder](/tools/theme-builder) pour les palettes, polices et échelles de rayon partagées. Ouvrir **Aperçu du tableau de bord** choisir la densité, l'échelle d'interface, la barre latérale, la largeur du contenu, la toile et le mouvement.

1. Choisissez vos couleurs et vos paramètres d'apparence.
2. Sélectionner **Télécharger Starter Pro config**puis remplacez `config/appearance.ts`.
3. Redémarrez l'application. Dans un navigateur avec des préférences enregistrées, utilisez Personnaliser pour réinitialiser.

Les choix de navigateur enregistrés ont priorité sur les paramètres par défaut du produit. Le mode de prévisualisation sélectionné devient le mode initial lumière/obscurité; `mode: "system"` dans la configuration pour suivre le périphérique. Les préréglages nommés utilisent les tokens partagés groupés. Les couleurs personnalisées incluent à la fois des cartes de couleurs sémantiques et apparaissent comme **Personnalisé** sur mesure.

Cette exportation nécessite la source Starter Pro avec `lib/appearance-contract.ts`. Pour un projet plus ancien, mettez à niveau d'abord ou utilisez les exportations CSS.

Le ZIP de l'acheteur inclut le contrat de configuration, les instantanés de couleurs et les ressources de police locales. Il ne nécessite pas de package d'espace de travail privé ni de serveur Theme Builder.

Adoptez les recettes explicitement dans votre propre projet. Le validateur de l'acheteur-ZIP applique son code à une copie extraite jetable, la compile et exerce des cas autorisés, refusés, révoqués et inter-espaces de travail. ## Conserver une base de référence de mise à niveau [#keep-an-upgrade-baseline]

Commit la livraison originale dans un dépôt privé avant la personnalisation. Conserver `PYCOLORS_RELEASE.json`, le fichier de verrouillage, les patchs, le changelog, les termes de licence et de commande. Comparez une livraison nouvellement disponible à cette base de référence et fusionnez vos adaptations par révision. L'accès aux versions futures suit l'offre achetée.

## Répéter les migrations [#rehearse-migrations]

<Steps>
  <Step>
    ### Réviser la version entrante [#review-the-incoming-release]

    Lisez le journal des modifications, SQL en attente et les modifications d'environnement avant l'installation.

</Step>
  <Step>
    ### Préparer une mise en scène restreinte [#prepare-restricted-staging]

    Restaurez une sauvegarde récupérable dans un environnement intermédiaire restreint.

</Step>
  <Step>
    ### Installer et inspecter le statut de migration [#install-and-inspect-migration-status]

    <CopyableCommand command="pnpm install --frozen-lockfile" />
    <CopyableCommand command="pnpm exec prisma migrate status" />

</Step>
  <Step>
    ### Appliquer les migrations révisées [#apply-reviewed-migrations]

    <CopyableCommand command="pnpm exec prisma migrate deploy" />

    Gardez les migrations déjà appliquées aux données conservées immuables. La migration projet-travail ajoute des tables de tâches/commentaires et préserve les projets existants.

</Step>
  <Step>
    ### Valider la application [#validate-the-application]

    Exécutez des diagnostics, des tests, une construction de production et les parcours utilisateur concernés. Les mises à niveau du registre de session peuvent obliger les utilisateurs à se connecter à nouveau.

</Step>
  <Step>
    ### Vérifier les fournisseurs avant le déploiement [#verify-providers-before-rollout]

    Vérifiez l'intégration du fournisseur dans un bac à sable avant de déployer le résultat révisé.

</Step>

</Steps>

<Callout title="Planifier la récupération avant le déploiement">
  Conservez l'artefact d'application précédent et vérifiez la compatibilité
  schéma/session avant la restauration. Il n’y a pas de down-migration
  automatique destructrice. Une restauration de base de données peut perdre des
  écritures après le point de récupération choisi ; utilisez votre procédure
  incidente.

</Callout>
