## Vue d’ensemble [#overview]

Starter Pro utilise des variables d'environnement pour séparer les problèmes d'infrastructure, d'authentification, de facturation, de livraison des e-mails et de déploiement en toute sécurité.

Ceci garde :

- secrets en dehors du dépôt
- Environnements prévisibles
- Déploiement portable
- infrastructure de facturation sécurisée
- Authentification Production-Safe

<Callout title="Principe de base">
  Les variables d'environnement définissent les limites de l'infrastructure
  entre votre base de code et les systèmes de production.

</Callout>

## Esprit de production [#production-mindset]

Starter Pro est conçu autour des exigences réelles de déploiement SaaS.

Cela signifie que les variables d'environnement devraient prendre en charge:

- développement local
- Mise en scène des déploiements
- infrastructure de production
- Stripe facturation
- Fournisseurs OAuth
- Authentification sécurisée
- isolation de la base de données

## Configuration de la base de données [#database-configuration]

Starter Pro utilise PostgreSQL avec Prisma.

```text title=".env.local"
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/starter_pro
```

Pratiques de production recommandées :

- Hébergement PostgreSQL géré
- sauvegardes automatisées
- séparation de mise en scène et de production
- connexion pooling
- Accès restreint à la base de données

<Callout type="info" title="Règle de production">
  Ne partagez jamais les informations d'identification de la base de données de
  production dans des environnements locaux ou des référentiels publics.

</Callout>

## Variables d'authentification [#authentication-variables]

Starter Pro utilise Auth.js pour l'authentification.

```text title=".env.local"
AUTH_SECRET=
AUTH_GOOGLE_ID=
AUTH_GOOGLE_SECRET=
AUTH_GITHUB_ID=
AUTH_GITHUB_SECRET=
AUTH_TRUST_HOST=true
```

### Requis [#required]

| Variable      | Objet                                                |
| ------------- | ---------------------------------------------------- |
| `AUTH_SECRET` | Signer des sessions et des tokens d'authentification |

### Fournisseurs optionnels [#optional-providers]

| Variable             | Objet                            |
| -------------------- | -------------------------------- |
| `AUTH_GOOGLE_ID`     | ID client Google OAuth           |
| `AUTH_GOOGLE_SECRET` | Le secret du client Google OAuth |
| `AUTH_GITHUB_ID`     | ID client GitHub OAuth           |
| `AUTH_GITHUB_SECRET` | GitHub OAuth client secret       |

### Notes [#notes]

- `AUTH_SECRET` Doit être forte en production
- Les fournisseurs OAuth sont facultatifs
- Email/mot de passe auth fonctionne sans OAuth
- Les domaines de production doivent correspondre à la configuration OAuth

## Livraison par email [#email-delivery]

Starter Pro prend en charge les flux d'e-mails transactionnels via Resend.

```text title=".env.local"
AUTH_RESEND_API_KEY=
AUTH_EMAIL_FROM="PyColors <noreply@your-domain.com>"
```

Les flux de courrier électronique comprennent:

- e-mails de vérification
- mot de passe reset emails
- livraison auth transactionnelle

## Variables de facturation Stripe [#stripe-billing-variables]

Starter Pro inclut des fondations de facturation Stripe prêtes pour la production.

```text title=".env.local"
STRIPE_SECRET_KEY=
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=
STRIPE_WEBHOOK_SECRET=

STRIPE_PRODUCT_PRO=
STRIPE_PRICE_PRO_MONTHLY=
```

### Variables de facturation de base [#core-billing-variables]

| Variable                             | Objet                       |
| ------------------------------------ | --------------------------- |
| `STRIPE_SECRET_KEY`                  | Accès Stripe côté serveur   |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | Intégration Frontend Stripe |
| `STRIPE_WEBHOOK_SECRET`              | Validation Webhook          |
| `STRIPE_PRODUCT_PRO`                 | ID produit Stripe           |
| `STRIPE_PRICE_PRO_MONTHLY`           | ID de prix Stripe           |

### Règles importantes [#important-rules]

- Les modes test et live sont séparés
- les produits et les prix doivent correspondre au même mode Stripe
- La validation du webhook est requise
- Les webhooks de production doivent utiliser HTTPS

```bash title="stripe-cli.sh"
stripe listen --forward-to localhost:3000/api/webhooks/stripe
```

<Callout title="Principe de facturation">
  La fiabilité de la facturation dépend davantage de la configuration correcte
  de Stripe que de la mise en œuvre frontale.

</Callout>

## Exemple de fichier d'environnement [#example-environment-file]

```text title=".env.example"
# -----------------------------------------------------------------------------
# Database
# -----------------------------------------------------------------------------
DATABASE_URL=

# -----------------------------------------------------------------------------
# App
# -----------------------------------------------------------------------------
NEXT_PUBLIC_APP_URL=
APP_BASE_URL=

# -----------------------------------------------------------------------------
# Auth
# -----------------------------------------------------------------------------
AUTH_SECRET=

AUTH_GOOGLE_ID=
AUTH_GOOGLE_SECRET=

AUTH_GITHUB_ID=
AUTH_GITHUB_SECRET=

AUTH_TRUST_HOST=true

# -----------------------------------------------------------------------------
# Email
# -----------------------------------------------------------------------------
AUTH_RESEND_API_KEY=
AUTH_EMAIL_FROM=

# -----------------------------------------------------------------------------
# Stripe
# -----------------------------------------------------------------------------
STRIPE_SECRET_KEY=
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=
STRIPE_WEBHOOK_SECRET=

STRIPE_PRODUCT_PRO=
STRIPE_PRICE_PRO_MONTHLY=
```

— Erreurs courantes

Évitez ces erreurs de déploiement :

- exposer publiquement des variables secrètes
- mélange de Stripe test et live IDs
- oubli de la configuration du webhook
- commiting `.env.local`
- Utiliser des secrets d'auth faibles
- partage des informations d'identification de production

<Callout type="info" title="Règle de sécurité">
  Les variables d'environnement font partie de votre modèle de sécurité de
  l'infrastructure, et pas seulement de la configuration des applications.

</Callout>

### Flux de travail recommandé [#recommended-workflow]

1. Configurer des variables locales
2. Valider les flux d'auth
3. valider le mode de test Stripe
4. valider la synchronisation webhook
5. Configurer les secrets de production
6. déployer la mise en scène
7. valider la facturation de production
8. lancement public
