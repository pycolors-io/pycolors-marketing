## Une facturation pour commercialiser votre produit [#billing-that-turns-your-product-into-a-business]

Starter Free fournit **les écrans de tarification et de facturation**.

Starter Pro fournit **les fondations d’une intégration Stripe réelle** :

- Stripe Checkout
- portail de facturation en libre-service
- association des comptes aux clients Stripe
- cycle de vie de l'abonnement
- synchronisation par webhooks
- suivi des factures
- droits d’accès selon l’offre

Ces fondations couvrent le fonctionnement de la facturation au-delà de la page de tarifs.

Elles permettent à votre SaaS d’accepter des paiements et de gérer les accès qui en dépendent.

  produit.

### Les besoins couverts [#what-this-solves]

Intégrer Stripe ne se limite pas à ajouter un bouton de paiement.

Une intégration de facturation SaaS doit couvrir :

- création de sessions de paiement
- association entre utilisateur et client Stripe
- gestion du statut des abonnements
- vérification des webhooks
- suivi des factures
- accès au portail de facturation
- Comportement du produit selon l’offre
- gestion des échecs de paiement
- comportement d'annulation

Starter Pro structure ces responsabilités pour vous permettre de les adapter à votre produit sans repartir de zéro.

## Cycle de vie de la facturation [#billing-lifecycle]

<Steps>
  <Step>
    ### L’utilisateur choisit une offre [#user-starts-upgrade]

    L’utilisateur demande une mise à niveau depuis les tarifs, la facturation ou une fonctionnalité réservée à une offre supérieure.

```txt title="entry-points.txt"
/pricing
/billing
/protected-feature
```

</Step>

  <Step>
    ### Le backend crée la session Checkout [#backend-creates-checkout-session]

    Le navigateur demande une session à votre serveur. Celui-ci crée la session Checkout avec les clés Stripe conservées côté serveur.

```ts title="server/billing/create-checkout-session.ts"
const session = await stripe.checkout.sessions.create({
  customer: stripeCustomerId,
  mode: "subscription",
  line_items: [{ price: priceId, quantity: 1 }],
  success_url: `${appUrl}/billing?success=true`,
  cancel_url: `${appUrl}/pricing?canceled=true`,
});
```

</Step>

  <Step>
    ### Stripe confirme le paiement [#stripe-confirms-payment]

    Stripe traite le paiement, crée l’abonnement et gère la facturation du client.

    Une redirection vers la page de confirmation ne suffit pas à prouver que le paiement a réussi.

</Step>

  <Step>
    ### Le webhook synchronise l’application [#webhook-updates-app-state]

    Les webhooks permettent au serveur de confirmer les événements survenus chez Stripe, puis de mettre à jour la base de données.

```txt title="webhook-events.txt"
checkout.session.completed
customer.subscription.created
customer.subscription.updated
customer.subscription.deleted
invoice.payment_succeeded
invoice.payment_failed
```

</Step>

  <Step>
    ### L'application reflète l'état de facturation [#app-reflects-billing-state]

    Les droits d’accès, la page de facturation et l’historique des factures doivent s’appuyer sur l’état synchronisé côté serveur.

</Step>

</Steps>

<Callout title="Règle de production">
  Les redirections guident l’utilisateur. Les webhooks permettent de confirmer et de synchroniser les événements de facturation.

</Callout>

## Architecture [#architecture]

### Responsabilités du modèle de données [#data-model-responsibilities]

Votre application doit pouvoir représenter le client Stripe, son abonnement et le statut de ses paiements.

Les principales responsabilités sont les suivantes :

| Zone         | Objet                                                   |
| ------------ | ------------------------------------------------------- |
| Client       | Associe les comptes de l’application aux clients Stripe |
| Produit      | Représente les produits SaaS vendables                  |
| Prix         | Représente les prix Stripe et les offres commerciales   |
| Abonnement   | Suivi de l'état actuel de l'abonnement                  |
| Facture      | Stocke les références de facture et l'état de paiement  |
| WebhookEvent | Traite les événements Stripe pour plus de fiabilité     |

<Callout type="info" title="Pourquoi cela compte">
  Stripe traite les paiements. Votre application doit conserver un état
  synchronisé pour appliquer les droits d’accès et afficher des informations
  de facturation cohérentes.

</Callout>

### Contrôler l’accès selon l’offre [#plan-gating]

Les informations de facturation permettent d’appliquer les règles d’accès du produit.

Starter Pro fournit les bases pour mettre en œuvre :

- des accès gratuits et payants
- des fonctionnalités activées selon l’offre
- vérification du statut de l'abonnement
- des paramètres tenant compte de la facturation
- invites de mise à niveau
- comportement d'annulation
- des messages en cas d’échec de paiement

```ts title="plan-access.ts"
export function canAccessProFeature(subscriptionStatus: string) {
  return subscriptionStatus === "active" || subscriptionStatus === "trialing";
}
```

Centralisez les règles de chaque offre et vérifiez-les côté serveur.

### Vérifications de l’intégration [#implementation-checklist]

Avant de traiter la facturation comme étant prête pour le lancement, validez :

- création de sessions de paiement
- retour après un paiement réussi
- retour après une annulation
- association des comptes aux clients Stripe
- création de session du portail de facturation
- vérification de signature webhook
- événement de création d’abonnement
- événement de modification d’abonnement
- annulation d’abonnement
- événement de paiement de facture réussi
- événement d’échec de paiement d’une facture
- logique d'accès selon l’offre
- État de la page de facturation
- messages d’erreur de facturation destinés à l’utilisateur

<Callout type="info" title="Principe de validation">
  Ne faites pas confiance à la facturation tant que vous n'avez pas validé le
  cycle de vie complet : paiement, webhook, synchronisation de la base de
  données et accès au produit.

</Callout>

## Questions fréquentes [#common-questions]

<Accordions type="single">
  <Accordion title="S’agit-il uniquement d’une page de tarifs ?">
    Non. Starter Pro comprend les fondations du paiement, du portail, des webhooks, du suivi des abonnements et des factures, ainsi que des droits d’accès selon l’offre.
  </Accordion>

<Accordion title="Puis-je commencer avec des paiements uniques au lieu d'abonnements?">
  Oui, en adaptant l’intégration à ce modèle. Conservez une séparation claire
  entre le client, le paiement et les droits d’accès. Ce choix métier reste
  distinct des fondations techniques fournies pour Stripe.
</Accordion>

<Accordion title="Le frontend doit-il décider si un utilisateur y a accès ?">
  Non. L’interface peut afficher les droits d’accès, mais leur application doit
  être contrôlée côté serveur à partir de l’état de facturation synchronisé.
</Accordion>

  <Accordion title="Pourquoi les webhooks sont-ils nécessaires ?">
    Une redirection ne suffit pas à confirmer un paiement. Les webhooks signalent à votre serveur les paiements, les renouvellements, les annulations et les échecs survenus chez Stripe.
  </Accordion>
</Accordions>
