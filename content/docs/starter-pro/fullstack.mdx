Starter Pro Fullstack is a one-time source licence combining the complete **Web application**, the **native iOS and Android application**, and their **shared API**. Web and Mobile use the same backend, accounts, workspace permissions and data after you configure them.

See the current tax-inclusive price on the [Fullstack product page](/starters/fullstack) and compare [source licences](/pricing#source-licences). This is source you configure and operate; hosting, third-party services and Apple/Google accounts are separate.

## One Web backend, two interfaces

The archive root is `pycolors-starter-pro-fullstack/`:

- `README.md` and `LICENSE` describe this release's setup, operating and licence boundaries.
- `PYCOLORS_RELEASE.json` records the purchased and included products, component paths, terms version, source revision and hashes.
- `web/` is the complete Starter Pro Web source, including the shared backend under `app/api`.
- `mobile/` is the independent Expo source, retained API client and native tokens.

There is no second backend fork to synchronize. Use one configured Web backend for both interfaces. The PyColors commerce storefront and hosted provider accounts are not application modules supplied in this archive.

## Follow one setup path

1. Inspect the received manifest and read the archive README. Configure the Web application from `web/` using [Web getting started](/docs/starter-pro/getting-started).
2. Review the [Web architecture](/docs/starter-pro/architecture), [backend boundaries](/docs/starter-pro/backend) and [server environment](/docs/starter-pro/environment-variables). Keep one database and a compatible API for both interfaces.
3. Install the independent `mobile/` source with the [Mobile guide](/docs/starter-pro/mobile#native-source), pointing it at that same backend. The [Web PWA](/docs/starter-pro/pwa) is a separate browser capability, not a substitute for native setup.
4. Configure your native identity and backend trust, then validate both interfaces against your own test environment. Owning both sources does not configure provider accounts or deploy either application automatically.

## Configure Web and the shared backend

Use the Node/pnpm versions and frozen lockfiles in the received release. Prepare PostgreSQL and configure the supplied environment examples for Better Auth, email, billing and the integrations you need.

From `web/`:

```sh
pnpm install --frozen-lockfile
pnpm db:generate
pnpm exec prisma migrate deploy
pnpm build
pnpm start
```

Follow [Web getting started](/docs/starter-pro/getting-started), applying its commands inside `web/`. The Web purchase licence and your own application's user subscriptions are separate. You configure your own Stripe products, prices and webhooks if you monetize the application.

## Connect Mobile to the same accounts and data

From `mobile/`, follow the [Mobile setup and qualification steps](/docs/starter-pro/mobile#native-source). Point its public endpoint at the Web application's shared backend:

```dotenv
EXPO_PUBLIC_STARTER_PRO_API_URL=https://your-web.example/api/rpc/v1
```

Use the same origin for the supported authentication lifecycle and RPC. Configure the permitted native callback/origins in the backend. A device or emulator must reach that HTTPS origin. Do not connect Mobile to the PyColors commerce API or create a second user database for the same Fullstack deployment.

Validate a real account and authorized workspace/project journey from both interfaces against your own test database. Your release's source and synthetic qualification results do not validate your provider configuration or deployment.

## Validate and distribute your own applications

Review the received manifest, hashes and exact qualification reports. Build and test Web, then run Mobile's API/token, lint, types, tests, config/dependency and Hermes export checks. Keep source versions aligned when upgrading the Web API and retained Mobile client.

Hermes exports are JavaScript/bytecode, not signed store binaries. Qualify installed-device behavior using your own native toolchains, identifiers, signing and Apple/Google accounts, and complete the stores' distribution requirements. No hosted service, native binary publication or store approval is included.
