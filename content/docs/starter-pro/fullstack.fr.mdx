Starter Pro Fullstack réunit en une licence source à paiement unique l’**application Web complète**, l’**application native iOS et Android** et leur **API commune**. Après configuration, Web et Mobile utilisent le même backend, les mêmes comptes, permissions d’espace et données.

Le [prix TTC figure sur la page Fullstack](/starters/fullstack). Comparez les [licences source](/pricing#source-licences). Vous configurez et exploitez ce code ; hébergement, services tiers et comptes Apple/Google sont séparés.

## Achat, upgrade et accès

Achetez Fullstack depuis sa page produit, ou ouvrez le lien privé d’un achat Web/Mobile éligible pour demander l’upgrade de cette commande vérifiée. Obtenez un nouveau lien par [récupération d’achat](/orders/recover). Une adresse e-mail publique ou un montant fourni par le client ne détermine jamais l’éligibilité ou le prix d’upgrade.

Seul un paiement vérifié autorise la nouvelle commande et ses droits. Utilisez l’e-mail Fullstack pour télécharger le bon ZIP. Gardez les liens privés. Si le paiement est incertain, contactez l’[assistance achat](/orders/support) avant de payer à nouveau. Confirmation du paiement, livraison de l’e-mail et téléchargement terminé restent des vérifications distinctes.

## Un backend Web, deux interfaces

La racine de l’archive est `pycolors-starter-pro-fullstack/` :

- `README.md` et `LICENSE` décrivent installation, exploitation et licence de cette version.
- `PYCOLORS_RELEASE.json` indique produits acheté/inclus, chemins des composants, version des conditions, révision source et empreintes.
- `web/` contient Starter Pro Web complet, dont le backend commun dans `app/api`.
- `mobile/` contient Expo autonome, le client API conservé et les tokens natifs.

Aucun deuxième fork backend n’est à synchroniser. Les deux interfaces utilisent un backend Web configuré. Le storefront commerce PyColors et les comptes de fournisseurs hébergés ne sont pas des modules livrés dans cette archive.

## Configurer Web et le backend commun

Utilisez les versions Node/pnpm et les lockfiles figés de la version reçue. Préparez PostgreSQL et les exemples de variables pour Better Auth, e-mail, facturation et les intégrations voulues.

Depuis `web/` :

```sh
pnpm install --frozen-lockfile
pnpm db:generate
pnpm exec prisma migrate deploy
pnpm build
pnpm start
```

Suivez le [démarrage Web](/docs/starter-pro/getting-started) depuis `web/`. L’achat de la licence PyColors est distinct des abonnements des utilisateurs de votre application. Si vous monétisez celle-ci, configurez vos propres produits, prix et webhooks Stripe.

## Connecter Mobile aux mêmes comptes et données

Depuis `mobile/`, suivez les [étapes d’installation et qualification Mobile](/docs/starter-pro/mobile#native-source). L’endpoint public vise le backend commun de l’application Web :

```dotenv
EXPO_PUBLIC_STARTER_PRO_API_URL=https://your-web.example/api/rpc/v1
```

Utilisez la même origine pour l’authentification supportée et le RPC. Configurez les callbacks/origines natives autorisés dans le backend. L’appareil ou l’émulateur doit atteindre cette origine HTTPS. Ne visez pas l’API commerce PyColors et ne créez pas une deuxième base d’utilisateurs pour ce même déploiement Fullstack.

Validez un vrai compte et un parcours autorisé d’espace/projet depuis les deux interfaces sur votre base de test. Les résultats source et synthétiques reçus ne valident pas votre configuration fournisseur ou votre déploiement.

## Valider et distribuer vos applications

Examinez manifeste, empreintes et rapports exacts reçus. Construisez et testez Web, puis exécutez les contrôles Mobile d’API/tokens, lint, types, tests, configuration/dépendances et exports Hermes. Gardez API Web et client Mobile conservé alignés lors des mises à jour.

Les exports Hermes sont du JavaScript/bytecode, pas des binaires signés de store. Qualifiez le comportement installé avec vos outils natifs, identifiants, signature et comptes Apple/Google, puis respectez les exigences de distribution des stores. Aucun hébergement, publication de binaire ou accord de store n’est inclus.
