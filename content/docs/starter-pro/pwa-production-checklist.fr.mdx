## Valider avant la publication [#validate-before-release]

Utilisez cette liste de contrôle avant d'expédier la couche PWA dans Starter Pro.

L’objectif est de valider :

- qualité manifeste
- qualité d'icône
- Qualité de capture d'écran
- Service Worker Comportement
- routage de secours hors ligne
- mode autonome
- UX mobile
- Comportement HTTPS de production

## Liste de contrôle manifeste [#manifest-checklist]

Valider dans Chrome DevTools :

```txt title="chrome-devtools.txt"
Application
→ Manifest
```

Confirmer:

- Le nom de l'application est correct
- Le nom court est correct
- `display` est `standalone`
- La couleur du thème est visible
- La couleur de fond est visible
- Les icônes sont détectées
- Les captures d'écran sont détectées
- Aucun avertissement d'installation n'apparaît

<Callout type="info" title="Règle de capture">
  Utilisez de vraies captures d’écran de tableau de bord ou d’espace de travail.
  Évitez d'utiliser uniquement les écrans de connexion car ils ne communiquent
  pas la valeur SaaS complète.

</Callout>

## Liste de contrôle hors ligne [#offline-checklist]

Valider le comportement hors ligne :

```txt title="chrome-devtools.txt"
Application
→ Service Workers
→ Offline
```

Rechargez ensuite l'app.

Résultat attendu :

- `/offline` renders
- page garde le style PyColors
- app ne plante pas
- L'action reload est présente
- aucune donnée périmée sensible n'est affichée

## Liste de contrôle mobile [#mobile-checklist]

Valider sur des appareils réels lorsque cela est possible :

- iPhone Safari
- Chrome Android
- mode autonome installé
- tableau de bord
- Page de facturation mobile
- Page des paramètres mobiles
- Page hors ligne mobile

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Le phare devrait-il être parfait avant l'expédition?">
    Non. Utilisez Lighthouse comme un signal, pas comme la seule porte de publication. La porte clé de la publication est de savoir si l'installabilité, le repli hors ligne, les icônes, les captures d'écran et le HTTPS de production sont corrects.
  </Accordion>

<Accordion title="Dois-je mettre en cache les routes authentifiées ?">
  Pas par défaut. Les routes SaaS authentifiées peuvent contenir des données
  sensibles ou périmées. Commencez par un comportement hors ligne de secours
  uniquement.
</Accordion>

  <Accordion title="Que dois-je tester sur iOS ?">
    Valider Ajouter à l'écran d'accueil, mode autonome, comportement de la barre d'état, ajustement de la fenêtre d'affichage et navigation mobile.
  </Accordion>
</Accordions>
