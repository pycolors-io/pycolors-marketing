## Architecture adaptées à la production [#production-shaped-architecture]

Starter Pro est conçu autour d'un principe :

> se déplacer rapidement sans détruire la maintenabilité à long terme.

L'architecture sépare clairement les préoccupations du produit:

- Routage
- Authentification
- facturation
- backend frontières
- structure du tableau de bord
- caractéristiques du produit
- primitives d'interface utilisateur partagées

Cela aide les équipes à faire évoluer la complexité du produit sans transformer la base de code en un monolithe de pages couplées et de logique dupliquée.

<Callout title="Principe de base">
  Starter Pro est structuré pour soutenir la croissance réelle du SaaS, pas
  seulement les démos locales.

</Callout>

## Architecture de haut niveau [#high-level-architecture]

```txt title="starter-pro-architecture.txt"
app
  ↓
route groups
  ↓
feature modules
  ↓
server boundaries
  ↓
database + billing + auth
  ↓
shared UI system
```

## Pourquoi cette structure existe [#why-this-structure-exists]

La plupart des bases de code SaaS deviennent difficiles à évoluer parce que :

- Auth Logic Fuites partout
- L'état de facturation devient incohérent
- pages dupliquer logique
- Les primitives de l'interface utilisateur s'éloignent
- Les frontières disparaissent
- Les responsabilités du serveur et du client se mélangent

Starter Pro est conçu pour réduire cette entropie dès le début.

<Callout type="info" title="Règle de production">
  L'architecture est conçue pour maintenir la vitesse du produit élevée après le
  lancement, et pas seulement avant le lancement.

</Callout>

## Flux de produits [#product-flow]

<Steps>
  <Step>
    ### Configurer l'infrastructure [#configure-infrastructure]

    Connectez la base de données, les fournisseurs d'authentification, la livraison de courrier électronique et l'infrastructure de facturation Stripe.

</Step>

  <Step>
    ### Gardez la fondation [#keep-the-foundation]

    Préservez l'authentification, la facturation, les mises en page, les paramètres, l'interpréteur de tableau de bord et la structure de routage protégée.

</Step>

  <Step>
    ### Remplacer les surfaces des produits [#replace-product-surfaces]

    Remplacez le contenu de démarrage, les étiquettes de navigation, les tableaux de bord et les flux spécifiques à un domaine par votre véritable logique produit.

</Step>

  <Step>
    ### Extension des modules de fonctionnalités [#extend-feature-modules]

    Ajoutez vos propres flux de travail métier tout en gardant les limites du serveur et les primitives d'interface utilisateur partagées stables.

</Step>

  <Step>
    ### Lancement incrémental [#launch-incrementally]

    Expédiez plus vite parce que la couche d'infrastructure est déjà adaptées à la production.

</Step>

</Steps>

## Philosophie de l'interface utilisateur partagée [#shared-ui-philosophy]

Starter Pro est livré avec un système de conception partagé déjà intégré.

Cela comprend :

- `@pycolors/ui`
- `@pycolors/tokens`
- Tailwind CSS v4
- tokens de couleur sémantiques
- primitives SaaS réutilisables
- accessibilité-premiers modèles

L’objectif est la cohérence entre :

- pages marketing
- App UI
- flux de facturation
- pages de paramètres
- dialogues et superpositions
- Surfaces de tableau de bord

<Callout title="La cohérence de l'IU est importante">
  Les produits SaaS se sentent plus premium lorsque la navigation, les
  superpositions, les formulaires, les paramètres et les surfaces de facturation
  se comportent de manière cohérente sur l'ensemble du produit.

</Callout>

## Ce que vous devez personnaliser [#what-you-should-customize]

Starter Pro est conçu pour être étendu, pas réécrit.

Vous remplacez généralement :

- branding
- copie
- étiquettes de navigation
- entités de domaine
- workflows produits
- contenu du tableau de bord
- stratégie de prix

Vous conservez généralement :

- auth fondations
- infrastructure de facturation
- protection de route
- tableau de bord shell
- paramètres architecture
- primitives d'interface utilisateur partagées
- structure du produit

### Modèle mental [#mental-model]

> Starter Pro n’est pas le produit final.
>
> C'est le système adaptées à la production que votre produit développe à l'intérieur.
