### Upgrade impact

The changes include additive database migrations for workspaces,
profiles, sessions, projects, notifications and locale preferences. The
project-work migration adds task and comment tables while preserving existing
projects. Rehearse the supplied migrations in isolated staging with a recoverable
backup; session-registry changes can require users to sign in again.

<Callout title="Billing and validation boundaries">
  Application billing remains attached to the **user account**. Resource quotas
  are configurable and **uncapped by default**. Signed billing regressions use a
  simulated provider; production email, Stripe configuration, alert routing and
  backups still require verification in your own environment.
</Callout>

Follow the [upgrade guide](/docs/starter-pro/customization-and-upgrades) and
[validation coverage](/docs/starter-pro/release-readiness) before installing a
new delivery.

## Migration expectations

Minor and patch releases aim to preserve compatibility. An additive feature can
still require a database migration; follow the notes for your exact delivery.
Review schema, environment and session changes before rollout and check whether
the previous application artifact can still run against the migrated schema.

The [customization and upgrades guide](/docs/starter-pro/customization-and-upgrades)
explains staging, validation and recovery. Retain the delivered
`PYCOLORS_RELEASE.json` when present to identify its source revision.
