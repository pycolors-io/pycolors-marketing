## Vue d’ensemble [#overview]

La plupart des bibliothèques d'interface s'arrêtent aux composants.

Les produits Real SaaS nécessitent une structure :

- navigation
- en-tête
- orchestration de contenu
- Comportement réactif
- Évolutivité à long terme

Ce guide montre comment composer des primitives PyColors dans un **réelle mise en page du produit** qui survit à la croissance.

<Callout title="Idée de base">
  La disposition n'est pas un composant. C’est une composition de
  responsabilités qui évolue au fil du temps.

</Callout>

### Modèle mental [#mental-model]

```tsx title="conceptual-layout.tsx"
<AppShell>
  <Sidebar />
  <Main>
    <Header />
    <Content />
  </Main>
</AppShell>
```

Ce n'est pas une API. Il s’agit d’une séparation des préoccupations :

- Navigation vers où vont les utilisateurs
- En-tête où les utilisateurs comprennent le contexte
- Contenu où les utilisateurs agissent

## Étapes [#steps]

<Steps>

<Step>
### Définir les responsabilités de mise en page [#define-layout-responsibilities]

Ne commencez pas par les composants. Commencez par les responsabilités :

- navigation (global)
- contexte (page-level)
- contenu (niveau de fonctionnalité)

Cela empêche les abstractions prématurées.

</Step>

<Step>
### Construire la navigation desktop-first [#build-desktop-first-navigation]

La disposition du bureau doit :

- garder la barre latérale visible
- préserver le balayage vertical
- Prise en charge des vues denses (tableaux, tableaux de bord)

La mise en page mobile devrait :

- Déplacer la navigation dans un panneau latéral
- prioriser le contenu
- exposer la navigation via un déclencheur

</Step>

<Step>
### Gardez l'en-tête léger [#keep-header-lightweight]

L'en-tête doit contenir :

- titre de la page
- description facultative
- action primaire
- menu utilisateur

Évitez de transformer l'en-tête en panneau de contrôle.

</Step>

<Step>
### Support de plusieurs types de contenu [#support-multiple-content-types]

Votre mise en page doit gérer :

- vues de données (tables, listes)
- flux de paramètres (formulaires, onglets)
- interactions modales (dialogues)

Une bonne mise en page ne change pas lorsque le contenu change.

</Step>

</Steps>

## Primaires de base [#core-primitives]

| Primitif       | Rôle                     |
| -------------- | ------------------------ |
| Bouton         | actions et déclencheurs  |
| Sheet          | navigation mobile        |
| Menu déroulant | actions contextuelles    |
| Onglets        | paramètres de navigation |
| Tableau        | Données structurées      |
| boîte dialogue | confirmations            |

<Callout type="info" title="Principe clé">
  Vous n’avez pas besoin d’un « système de mise en page ». Vous avez besoin de
  primitives fiables et d'une bonne composition.

</Callout>

## Quand introduire un AppShell [#when-to-introduce-an-appshell]

Créez votre propre AppShell lorsque :

- La répétition devient réelle
- Plusieurs équipes contribuent
- La complexité de la navigation augmente
- La cohérence devient critique

Pas avant.

### Résumé [#summary]

- La disposition est une composition, pas un composant
- Séparer les responsabilités
- Utiliser des primitives, pas des abstractions magiques
- Structure d'échelle seulement quand nécessaire

<Callout title="Prochaine étape">
  Combinez cette disposition avec des états et des formes asynchrones pour
