## Vue d’ensemble [#overview]

Les produits modernes passent une grande partie de leur vie en dehors du chemin du bonheur.

Charges de données. Les listes sont vides. Les demandes échouent. Les actions peuvent être retardées, rejetées, rejugées ou bloquées par des autorisations.

La façon dont votre produit gère ces moments affecte directement :

- Performance perçue
- Confiance des utilisateurs
- clarté du produit
- qualité globale du produit

Ce guide explique comment concevoir **chargement**, **vide**et **erreur** avec PyColors UI primitives.

<Callout title="Pourquoi cela compte">
  Les utilisateurs ne se contentent pas de juger de l’état de réussite. Ils
  jugent également si le produit se sent stable lorsque les données sont
  manquantes, lentes ou indisponibles.

</Callout>

### Modèle mental [#mental-model]

> Le squelette est une forme. EmptyState est une explication. L’alerte est un problème.

Chaque état asynchrone a un travail:

| État       | Composante   | Signification                                                    |
| ---------- | ------------ | ---------------------------------------------------------------- |
| Chargement | `Skeleton`   | Les données sont attendues bientôt                               |
| Vide       | `EmptyState` | La demande a fonctionné, mais il n'y a rien à montrer            |
| Erreur     | `Alert`      | Quelque chose a échoué et l'utilisateur a besoin de commentaires |

<Callout type="info" title="Règle du système">
  Ne floutez pas les états asynchrones. Un produit se sent plus clair lorsque
  chaque état communique une situation spécifique.

</Callout>

## Étapes [#steps]

<Steps>

<Step>
### Utiliser Skeleton pour le chargement [#use-skeleton-for-loading]

Utilisation `Skeleton` lorsque les données sont chargées et que la disposition finale est déjà connue.

Le squelette doit préserver la forme et réduire le décalage de mise en page. Cela ne devrait pas expliquer l’État.

<Tabs items={["Carte", "Tableau"]}>
  <Tab value="Carte">

```tsx title="components/project-card-skeleton.tsx"
import { Card, CardContent, Skeleton } from "@pycolors/ui";

export function ProjectCardSkeleton() {
  return (
    <Card className="rounded-2xl border-border/60">
      <CardContent className="space-y-3 p-6">
        <Skeleton className="h-5 w-1/3" />
        <Skeleton className="h-4 w-2/3" />
        <Skeleton className="h-24 w-full" />
      </CardContent>
    </Card>
  );
}
```

</Tab>

  <Tab value="Tableau">

```tsx title="components/project-table-skeleton.tsx"
import { Skeleton, Table, TableBody, TableCell, TableRow } from "@pycolors/ui";

export function ProjectTableSkeleton() {
  return (
    <Table>
      <TableBody>
        {Array.from({ length: 3 }).map((_, index) => (
          <TableRow key={index}>
            <TableCell>
              <Skeleton className="h-4 w-32" />
            </TableCell>
            <TableCell>
              <Skeleton className="h-4 w-24" />
            </TableCell>
            <TableCell>
              <Skeleton className="h-4 w-16" />
            </TableCell>
          </TableRow>
        ))}
      </TableBody>
    </Table>
  );
}
```

</Tab>

</Tabs>

</Step>

<Step>
### Utiliser EmptyState pour les résultats vides valides [#use-emptystate-for-valid-empty-results]

Utilisation `EmptyState` lorsque la demande a réussi mais qu'il n'y a rien à afficher pour l'instant.

Un état vide devrait répondre à deux questions :

- Pourquoi est-ce vide ?
- Que peut faire l'utilisateur ensuite ?

```tsx title="components/projects-empty-state.tsx"
import { Button, EmptyState } from "@pycolors/ui";

export function ProjectsEmptyState() {
  return (
    <EmptyState
      title="No projects yet"
      description="Create your first project to start organizing your workspace."
      action={<Button>Create project</Button>}
    />
  );
}
```

Ce n'est pas un échec. C’est un véritable état de produit.

</Step>

<Step>
### Utiliser l'alerte pour les erreurs [#use-alert-for-errors]

Utilisation `Alert` lorsqu'une requête ou une action échoue et que l'utilisateur doit comprendre ce qui s'est passé.

```tsx title="components/projects-error-state.tsx"
import { Alert, AlertDescription, AlertTitle, Button } from "@pycolors/ui";

export function ProjectsErrorState() {
  return (
    <Alert variant="destructive">
      <AlertTitle>Projects could not be loaded</AlertTitle>
      <AlertDescription>Check your connection and try again.</AlertDescription>
      <div className="mt-4">
        <Button variant="outline">Retry</Button>
      </div>
    </Alert>
  );
}
```

La copie d'erreur doit être calme, spécifique et exploitable.

</Step>

</Steps>

## Guide de décision [#decision-guide]

Utilisation `Skeleton` lorsque:

- Les données sont en cours de chargement
- La mise en page est prévisible
- Le contenu est attendu prochainement
- vous voulez éviter le décalage de mise en page

Utilisation `EmptyState` lorsque:

- La demande a réussi
- Le résultat est valide
- Il n'y a rien à afficher
- L’utilisateur a besoin d’une prochaine étape

Utilisation `Alert` lorsque:

- Une demande a échoué
- Une action a échoué
- L'utilisateur ne peut pas continuer
- le produit doit expliquer un problème de blocage

<PreferAvoid
  prefer={[

### Liste de contrôle [#action-checklist]

Avant d'expédier des états async, confirmez que :

- les états de chargement préservent la mise en page lorsque cela est possible
- Les états vides expliquent pourquoi rien n'est montré
- Les états vides offrent une action suivante utile le cas échéant.
- L'erreur explique ce qui s'est passé
- les défaillances de blocage sont visibles en ligne, non seulement dans un toast
- Les actions de réessai sont disponibles lorsque la récupération est possible
- copie reste calme, spécifique et humain

## Questions courantes [#common-questions]

<Accordions type="single">
  <Accordion title="Dois-je utiliser un spinner au lieu de Skeleton?">
    Utilisez une toupie lorsque la mise en page est inconnue ou que l'opération est courte et isolée. Utilisez Skeleton lorsque la forme du contenu est déjà connue.
  </Accordion>

<Accordion title="Un état vide est-il une erreur ?">
  Non. Un état vide signifie que la requête a réussi mais n'a renvoyé aucun
  contenu utilisable. Le traiter comme une erreur rend le produit inutilement
  négatif.
</Accordion>

  <Accordion title="Faut-il afficher les erreurs de blocage comme des toasts ?">
    Habituellement non. Les toasts sont temporaires. Le blocage des défaillances doit rester visible en ligne afin que les utilisateurs puissent lire, comprendre et récupérer.
  </Accordion>
</Accordions>
