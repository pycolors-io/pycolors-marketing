## Vue d’ensemble [#overview]

Les actions asynchrones sont les endroits où la qualité du produit devient visible.

Contrairement à la récupération de données, les actions **changer la réalité**:

- enregistrer des données
- supprimer du contenu
- Déclenchement de la logique commerciale
- Mise à jour de l'état utilisateur

Ce guide définit comment gérer les mutations d'une manière qui se sent:

- rapide
- fiable
- Compréhensible
- prêt pour la production

<Callout title="Principe clé">
  Le chargement est une question d'attente. Les actions sont basées sur la
  confiance.

</Callout>

## Niveaux de rétroaction [#feedback-tiers]

| Niveau         | Quand utiliser                             |
| -------------- | ------------------------------------------ |
| Inline         | attendues, les changements locaux          |
| Toast          | Confirmation ou échec sans blocage         |
| boîte dialogue | Des actions destructrices ou irréversibles |

Ne jamais mélanger les rôles.

### Messagerie d'erreur [#error-messaging]

Bons messages d'erreur :

- Expliquer ce qui a échoué
- Suggérer quoi faire ensuite
- Restez calme et clair

## Motifs communs [#common-patterns]

### Enregistrer le flux [#save-flow]

- État de chargement en ligne
- toast succès ou erreur
- Réessayer en cas d'échec

### Supprimer le flux [#delete-flow]

- boîte de dialogue de confirmation
- toast avec undo
- Réessayez si la restauration échoue

### Basculer le flux [#toggle-flow]

- changement instantané d'interface utilisateur
- rollback sur erreur
- toast feedback

### Pourquoi cela compte [#why-this-matters]

Les actions asynchrones sont l'un des plus grands signaux de confiance dans un produit.

Mauvaise mutation UX conduit à:

- hésitation
- clics répétés
- confusion
- Perte de confiance

Bonne mutation UX se sent:

- rapide
- prévisible
- coffre-fort

C'est là que les produits commencent à se sentir **prêt pour la production**.
