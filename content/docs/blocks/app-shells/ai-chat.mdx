## A conversation that fits your application

`AIChat` brings a clear empty state, readable conversation and accessible
[AIComposer](/docs/ui/ai-composer) together. You supply messages, draft and request
state. Your application owns the backend, credentials, storage and cancellation.
The Block has no AI runtime dependency and makes no network requests.

Send, stop, retry and copy remain useful Free features. There are no file uploads,
tools, agent deployment, voice, rich Markdown or message persistence in this Block.
Text is rendered literally, including code and HTML characters.

## State and action ownership

| Prop                     | Responsibility                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------- |
| `messages`               | Ordered user/assistant text with stable unique IDs. Update the same ID while streaming.           |
| `draft`, `onDraftChange` | Your controlled input. Suggestions prefill without sending.                                       |
| `status`                 | `idle`, `submitting`, `streaming`, `stopped` or `error`.                                          |
| `onSubmit(draft)`        | Accept a nonblank request and set busy synchronously. The Block never clears the draft.           |
| `onStop`                 | Optional transport cancellation. Set stopped only after cancellation settles; reject late chunks. |
| `onRetry`                | Optional retry of the last failed/stopped request, not the newer draft. No automatic retry.       |
| `onCopy(message)`        | Promise resolving after a successful clipboard write, rejecting on failure.                       |
| `errorMessage`           | Safe user-facing error. Never expose raw provider errors or credentials.                          |
| `disabled`               | Disable input and mutation actions while retaining readable messages.                             |
| `ref`                    | Native textarea ref for consumer focus management.                                                |

Pass `onCopy={(message) => navigator.clipboard.writeText(message.text)}` in a client
component. The UI confirms only completed copies and offers manual selection on
failure. Copy during streaming copies the text at click time, not future tokens.

Keep submitted text in your message/request state before clearing an accepted
draft. Failures must preserve newer edits. Stop/retry must keep partial output
visible until replacement starts and must not duplicate the user message.

## Define an agent in the conversation

Pass the optional `agentDefinition` prop to add inline review. Omitting it keeps
basic chat unchanged. A supplied draft, a suggestion click or model text never
confirms anything. Only the separate **Confirm definition** action calls your
consumer. The composer and the review form are independent sibling forms.

| Field or callback            | Contract                                                                                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `draft`                      | Required `id`, `revision`, `name`, `purpose`, `instructions`. Keep IDs stable; increment revision on every edit, including capabilities and provenance.                   |
| `status`                     | `draft`, `confirming`, `created`, `error` or `cancelled`, supplied by your application.                                                                                   |
| `requestedCapabilities`      | Optional read-only strings describing requests. These are **not granted permissions**.                                                                                    |
| `sourceReferences`           | Optional read-only `{ id, label }` provenance. Labels render as text; no links are fetched and no file content is read.                                                   |
| `onChange(fields)`           | Receives only editable name/purpose/instructions. Preserve the other fields, increment revision and clear resolved validation errors.                                     |
| `errors`, `errorMessage`     | Safe field errors and confirmation error. Name/purpose/instructions must be nonblank; perform authoritative validation in your consumer.                                  |
| `onConfirm(snapshot)`        | Detached snapshot of the reviewed ID, revision and allowlisted fields. Set `confirming` synchronously and settle every attempt.                                           |
| `onCancel({ id, revision })` | Invalidate pending work and set `cancelled`. This is not remote deletion. Values remain readable.                                                                         |
| `confirmed`                  | Required with `created`: the actual consumer-confirmed snapshot. Copy/export is offered only when identity, revision and approved fields still match the displayed draft. |

Pending confirmation disables editing and repeated submission; cancel remains
available. Retry keeps edits and submits the current revision. The Block prevents
duplicate UI confirmation, but backend validation, idempotency, request identity,
transport cancellation and persistence remain your responsibility. Ignore stale
results after cancellation, replacement or unmount. Any server-modified definition
must return as a new draft for review, not as a silently approved result.

This complete local consumer maps **one exact sample request** to a draft. It does
not infer intent from arbitrary text. Its default confirmation returns the
reviewed snapshot in memory. The `confirm` callback is an application seam, not a
bundled backend or provider. A real intent/model adapter supplies the same typed
draft after validating untrusted output; it must still require explicit review.

```tsx title="src/components/agent-chat.tsx"
"use client";

import * as React from "react";
import {
  AIChat,
  type AgentDefinitionDraft,
  type AgentDefinitionState,
  type ChatMessage,
} from "./blocks/ai-chat";

const sampleRequest = "Define a product review assistant.";

// Local definition creation only. No provider, storage or agent runtime.
export function AgentChat({
  confirm = async (snapshot) => snapshot,
}: {
  confirm?: (snapshot: AgentDefinitionDraft) => Promise<AgentDefinitionDraft>;
}) {
  const [text, setText] = React.useState("");
  const [messages, setMessages] = React.useState<ChatMessage[]>([]);
  const [agent, setAgent] = React.useState<AgentDefinitionState>();
  const generation = React.useRef(0);
  const sequence = React.useRef(0);
  const pending = React.useRef(false);
  React.useEffect(
    () => () => {
      generation.current++;
    },
    [],
  );

  return (
    <AIChat
      messages={messages}
      draft={text}
      status="idle"
      onDraftChange={setText}
      onCopy={(message) => navigator.clipboard.writeText(message.text)}
      suggestions={[
        {
          id: "sample",
          label: "Define an agent (sample)",
          prompt: sampleRequest,
        },
      ]}
      onSubmit={(prompt) => {
        const id = `request-${++sequence.current}`;
        setMessages((current) => [
          ...current,
          { id, role: "user", text: prompt },
          {
            id: `${id}-reply`,
            role: "assistant",
            text:
              prompt.trim() === sampleRequest
                ? "Simulated draft from the exact sample request. Review and confirm below."
                : "This example recognizes only the exact sample request. It does not interpret arbitrary text.",
          },
        ]);
        setText("");
        if (prompt.trim() !== sampleRequest) return;
        generation.current++;
        pending.current = false;
        setAgent({
          status: "draft",
          draft: {
            id,
            revision: 0,
            name: "Product reviewer",
            purpose: "Review a supplied product interface.",
            instructions:
              "Check clarity, keyboard access and error recovery. Ask before expanding scope.",
          },
        });
      }}
      agentDefinition={
        agent
          ? {
              ...agent,
              onChange: (fields) => {
                generation.current++;
                setAgent((current) =>
                  current
                    ? {
                        status: "draft",
                        draft: {
                          ...current.draft,
                          ...fields,
                          revision: current.draft.revision + 1,
                        },
                      }
                    : current,
                );
              },
              onCancel: ({ id, revision }) => {
                generation.current++;
                pending.current = false;
                setAgent((current) =>
                  current?.draft.id === id &&
                  current.draft.revision === revision
                    ? { status: "cancelled", draft: current.draft }
                    : current,
                );
              },
              onConfirm: async (snapshot) => {
                if (pending.current) return;
                pending.current = true;
                const token = ++generation.current;
                setAgent({ status: "confirming", draft: snapshot });
                try {
                  const confirmed = await confirm(snapshot);
                  if (token !== generation.current) return;
                  // This contract confirms the reviewed snapshot, never changed server output.
                  // If validation changes fields, return a new draft for another review instead.
                  setAgent((current) =>
                    current?.status === "confirming" &&
                    current.draft.id === snapshot.id &&
                    current.draft.revision === snapshot.revision
                      ? { status: "created", draft: current.draft, confirmed }
                      : current,
                  );
                } catch {
                  if (token === generation.current)
                    setAgent({
                      status: "error",
                      draft: snapshot,
                      errorMessage:
                        "Confirmation failed. Your edits are preserved; retry when ready.",
                    });
                } finally {
                  if (token === generation.current) pending.current = false;
                }
              },
            }
          : undefined
      }
    />
  );
}
```

### Copy and download contract

After the consumer confirms the matching revision, the Block shows **Definition
created locally**. It does not mean deployed, running, connected or stored remotely.
Copy awaits the browser clipboard result; failures leave selectable JSON under
**Definition JSON**. Download requests a local `agent-definition.json` file and
reports the request, not proof that the browser saved it.

JSON uses this PyColors example format, not a universal cross-provider standard:

```json
{
  "schemaVersion": 1,
  "kind": "pycolors-agent-definition",
  "name": "Product reviewer",
  "purpose": "Review a supplied product interface.",
  "instructions": "Check clarity and keyboard access."
}
```

Optional `requestedCapabilities: string[]` and `sourceReferences: { id, label }[]`
are included when present. Export uses an explicit allowlist; draft identity,
revision, unknown properties, hidden grants and raw file payload properties are
excluded. It **does not redact secrets typed into allowed fields**. Do not supply
credentials, tokens, private file content or sensitive provenance labels. Export
is a view definition; interpreting it, storing it and authorizing tools require
your own separately reviewed application integration.

## Optional AI SDK integration

The Block works without an SDK. If your application uses AI SDK, the recipe below
maps its state to the same controlled props. It was checked with `ai@7.0.138` and
`@ai-sdk/react@4.0.141` in an isolated consumer using a mock transport. Real-provider
execution was **not run**. Install these only in your consuming application;
never add a provider dependency to the copied Block.

Your server owns `/api/chat`, authentication, input validation, credentials,
limits and cancellation. This guide does not provision that endpoint. Client
cancellation alone cannot guarantee that upstream generation or billing stops.
Review the [official useChat reference](https://ai-sdk.dev/docs/reference/ai-sdk-ui/use-chat)
for your installed version.

```tsx title="src/components/connected-chat.tsx"
"use client";

import * as React from "react";
import { useChat } from "@ai-sdk/react";
import { DefaultChatTransport, type ChatTransport, type UIMessage } from "ai";
import { AIChat, type ChatMessage, type ChatStatus } from "./blocks/ai-chat";

// Keep this adapter in your application, outside the copied Block.
export function ConnectedChat({
  transport,
}: {
  transport?: ChatTransport<UIMessage>;
}) {
  const [defaultTransport] = React.useState(
    () => new DefaultChatTransport({ api: "/api/chat" }),
  );
  const chat = useChat({ transport: transport ?? defaultTransport });
  const [draft, setDraft] = React.useState("");
  const [pending, setPending] = React.useState(false);
  const [stopped, setStopped] = React.useState(false);
  const [localError, setLocalError] = React.useState(false);
  const [previous, setPrevious] = React.useState<ChatMessage[] | null>(null);
  const inFlight = React.useRef(false);
  const mounted = React.useRef(false);
  React.useEffect(() => {
    mounted.current = true;
    return () => {
      mounted.current = false;
      void chat.stop();
    };
  }, [chat.stop]);

  const messages: ChatMessage[] = chat.messages.flatMap((message) => {
    if (message.role !== "user" && message.role !== "assistant") return [];
    const text = message.parts
      .filter((part) => part.type === "text")
      .map((part) => part.text)
      .join("");
    const unsupported = message.parts.some(
      (part) => part.type !== "text" && part.type !== "step-start",
    );
    return [
      {
        id: message.id,
        role: message.role,
        text: unsupported
          ? `${text}\n[Unsupported response content. This example supports text only.]`
          : text,
      },
    ];
  });
  const unsupported = chat.messages.some((message) =>
    message.parts.some(
      (part) => part.type !== "text" && part.type !== "step-start",
    ),
  );
  const busy =
    pending || chat.status === "submitted" || chat.status === "streaming";
  const status: ChatStatus =
    chat.status === "streaming"
      ? "streaming"
      : busy
        ? "submitting"
        : unsupported || localError || chat.status === "error"
          ? "error"
          : stopped
            ? "stopped"
            : "idle";
  const latest = messages.at(-1);
  // regenerate removes the old assistant message immediately. Preserve it until
  // its replacement has content; also retain it if retry fails before a chunk.
  const visible =
    previous && !(latest?.role === "assistant" && latest.text)
      ? previous
      : messages;

  async function request(retry: boolean, text: string) {
    if (inFlight.current || (!retry && !text.trim())) return;
    inFlight.current = true;
    setPending(true);
    setStopped(false);
    setLocalError(false);
    setPrevious(retry ? visible : null);
    chat.clearError();
    try {
      if (retry) await chat.regenerate();
      else await chat.sendMessage({ text });
    } catch {
      if (mounted.current) setLocalError(true);
    } finally {
      inFlight.current = false;
      if (mounted.current) setPending(false);
    }
  }

  return (
    <AIChat
      messages={visible}
      draft={draft}
      onDraftChange={setDraft}
      status={status}
      onSubmit={(text) => {
        void request(false, text);
      }}
      onRetry={
        chat.messages.some((message) => message.role === "user")
          ? () => {
              void request(true, "");
            }
          : undefined
      }
      onStop={() => {
        void chat
          .stop()
          .then(() => {
            if (mounted.current) setStopped(true);
          })
          .catch(() => {
            if (mounted.current) setLocalError(true);
          });
      }}
      onCopy={(message) => navigator.clipboard.writeText(message.text)}
      errorMessage={
        unsupported
          ? "The endpoint returned unsupported content. Configure a text-only response."
          : "The response could not be completed. Your text is preserved; you can retry."
      }
    />
  );
}
```

This example retains the draft until you edit it. A production consumer may clear
an accepted draft after retaining its request snapshot; never overwrite newer edits.
Keep the transport instance stable. Supply a custom `transport` only for your
application integration or tests; no provider or transport is bundled in the Block.

## Accessibility and limitations

Desktop Enter sends; Shift+Enter inserts a newline. IME composition never submits.
On touch-first devices Enter stays a newline; the explicit send action remains.
The composer owns a form, so do not nest the Block in another form.

The message list is not a token-by-token live region. A separate status announces
request transitions. Focus stays in the composer when sending and returns there
when a focused stop/retry control disappears. Incoming text does not steal focus.
The agent review uses labelled fields and a separate status. Incoming drafts do
not autofocus. Confirmation/cancellation returns focus to its result only when
the initiating focus is still inside the form or was lost; other controls keep
focus. Failed required validation focuses the first invalid field.
Scrolling up pauses following; **Jump to latest** explicitly resumes it.

The source uses semantic tokens, text wrapping and reduced-motion-safe controls.
Test your own callbacks, labels, locale, screen reader and physical mobile/IME
behavior. Automated accessibility checks do not certify an integration.
